## A warning for forms that would post to this computer · v0.21.0 (2026-11-15)

`service.py`: `Studio.audit()` now answers `GET /api/audit`, the MCP tool `audit_site` and the resource `formweb://audit`; it returns the engine's audit and adds one finding, code `forms.local-address`, per form that a plain export would point at this computer. Why here and not in the Rust audit: only the backend knows which address an export gets and for what purpose. A plain export (Export static site, `export_site`, Send to FormPublisher) passes `formsEndpoint: PUBLIC_BASE`, the bare loopback address, and its files leave this computer; Publish and Preview pass an address under `/published/` or `/preview/` for copies FormWeb itself serves, where the form works, so they call neither `audit()` nor `export_files()` and are never flagged. Why the finding is read from an export instead of re-stating the exporter's rule in Python: the rule (a `form` node that is not a script form and has no action of its own gets `action`, `method` and `data-fw-form="true"`) lives in `formweb-export`; `local_forms()` asks the engine for a plain export, finds each `<form data-fw-node="..." ... data-fw-form="true">` in the files `routes.json` lists, and names the page of that route, so the audit cannot disagree with what the export writes. The export runs only when the site has a `form` node at all and `local_address(PUBLIC_BASE)` is true (loopback, private, link-local, `localhost`, `.local`, a bare host name), and a refused export (a gated site) simply adds nothing. `export_files()` replaces its old sentence ("Form submissions use the local FormWeb backend ...") with the same findings' messages, one per page, in the export's `warnings`. The message is one English sentence with the page name; the editor shows its translation (frontend log). No file under `native/` changed. Checked: the product-site starter (six forms, all with a submit script) and the three demos (two forms, both scripted) get no finding; a sample site with an inserted form gets one, with the page and the form's node id; the same form with an action of its own gets none; the plain export's warnings carry the sentence, the Preview result's warnings and the Publish result's do not, and the published form's action is under `/published/`; 115 backend tests.

## Review fixes in the service · v0.21.0 (2026-11-15)

Commit 8aabcb4, backend part. `engine.py`: the whole app could go dead until restart with "Rust engine protocol response mismatch" on every route. Cause: `GET /api/events` first asks the engine for the state inside the streaming response; a page reload cancels that task between the request line being written and the reply being read; the lock was released, the unread reply stayed in the pipe, and every later request read the reply before its own. The mismatch was raised as an `EngineError`, which the transport handler does not catch, so the core was never restarted. Now `request()` takes the lock and then runs the exchange in a shielded task (`asyncio.shield`) whose `finally` releases the lock: a cancelled caller goes away at once, the exchange still reads its own reply, and the lock is free only after that. The lock is taken outside the shield on purpose, so a caller cancelled while waiting for the lock does no work (shielding the whole call made every dropped connection queue a full state exchange). A mismatch is now a `ValueError`, which takes the existing path: stop the core, answer 503 once, restart from the cached checkpoint on the next request. `assets.py` `bundle_assets()`: asset URLs were made relative to each file's depth, so the root `404.html`, which hosts serve at any missing address, asked for its fonts, icons and posters under the missing folder; that one file now takes the root prefix its own runtime link carries. `library_routes.py`: a section inserted on a blank site kept the sample's root padding and its `ink` and `paper` tokens (dark text on dark bars, side strips), because the preset only filled values the site lacked; a site with one empty page now takes the preset whole, an empty page root takes the preset's page styles, and the pages a starter adds take them too (they had 64 px padding and Arial). `library.py` `expand(..., demote)`: an inserted h1 becomes h2 when the page already has one, on insert and across a starter's sections. `formweb_engine.py`: `--selfcheck` also starts the bundled `formweb-core --selfcheck`, so a core that is present but cannot run fails the build; `uvicorn.run(..., timeout_graceful_shutdown=2)`, because on quit the web view's event stream is still open, uvicorn waited for it, the shell killed the group after 5 s and the one-file engine never removed the folder it unpacked. Checked: `race.py` (event streams dropped while health is polled) killed the old build within 300 connections and leaves the new one healthy after 800; `/a/b` on an exported site 7 failed requests before, 0 after; the starter on a blank site has full-bleed pages and one h1 on five of six pages; the frozen engine on Linux passes the selfcheck and, stopped with a stream open, exits in 2.5 s and removes its folder; a data folder made by 0.20.8 (three projects, a publication, an unsaved open site) opens with the same state, undo and exports; 115 tests. Known: the starter's Stories page has no h1; the preset's `ink-faint` on `float` is 4.33 to 1.

## Opening a .fpub package · v0.20.4 (2026-11-11)

`fpub.py` `is_fpub` and `read_fpub`, called from the `POST /api/load` path: a zip whose first entry is `fpub.json` is a FormPublisher package, not a `.fweb` archive. It must hold exactly `fpub.json`, `publish.json`, `site.zip` and, when signed, `site.zip.sig`, in that order. The checks are the format (`formpublisher-package`, version 1), the package record, `publish.json` repeating that record, the signature record matching the entries, and `site.zip` matching the recorded size and sha256 (streamed to `DATA_DIR/tmp` while counted, capped at the 512 MiB archive limit). Then `site.formweb.json` is read from `site.zip` (8 MiB cap), its `assets/` references are rewritten to `/api/assets/`, and each asset the site uses is staged in the asset folder with the usual size, digest and magic-byte checks (at most 500). The result is a version 2 project object restored like a `.fweb` archive; nothing is stored before every check passes and staged files are removed on a refusal. A `.fpub` without `site.formweb.json` is refused with a message pointing to FormPublisher. The signature (`site.zip.sig`) is not verified here; FormPublisher verifies it when it opens the same file.

Exit run: FormPublisher saved a signed `.fpub` of a FormWeb site (two pages, an image); a second FormWeb opened it with the same pages and nodes and the image stored under the same sha256 id. A `.fpub` with one flipped byte in `site.zip` was refused by both apps and left the FormWeb document unchanged.

## Cross-site requests with no Origin · v0.18.2 (2026-10-25)

`app/main.py` `LocalAccess`. The family agent-stack standard, rule G4 (`AGENT_STACK_STANDARD.md` v0.2.0, owner decision D4, ledger FB-035, formai_dev sidecar). The middleware let a request with no Origin through once its Host was an exact loopback name, so a web page could make the engine answer a GET by pointing an `<img>` or a link at `http://127.0.0.1:<port>/...`: browsers send no Origin on those, and any GET route with a side effect would run.

The rule: a request that carries no Origin is refused with 403 "Cross-site requests are not allowed." when `Sec-Fetch-Site` is `cross-site` (trimmed, case-insensitive), except on the paths `LocalAccess` already treats as public (`public`: the form submit route `/api/forms/<site>/<form>`, `/api/runtime/`, the commerce webhook, and `/published/`, `/sites/` and `/preview/`). Those are meant to be reached by pages on other sites and are gated by their own tokens, signatures or content; the exception is left as it was. A request that carries an Origin is decided by the existing Origin rule alone. `same-site` stays allowed on purpose: a dev window on `localhost:5240` loading straight from `localhost:8240` is same-site, and no outside page can be same-site with localhost. The CLI, `setup/mcp_stdio.py` and Claude Code's MCP client send neither header and pass. The middleware is `http` only; browsers always send an Origin on a websocket.

Checked on the running engine (port 9126) at `/api/health`: no Origin with `cross-site` and with `  Cross-Site ` 403; `same-site`, `same-origin`, `none`, no header, and `cross-site` with the dev Origin `http://localhost:5240` 200; a foreign Host 421 and `Origin: http://evil.example` 403 as before; `/api/system` cross-site 403; `/published/x/` cross-site 404 (the public path, not refused). ## Runtime boundary

`app/engine.py` supervises one Rust JSON-lines subprocess with one asyncio lock. Standard output carries protocol replies only. Core stderr is drained into the Python logger. Requests use increasing IDs and a 30-second acknowledgement timeout. Engine failures leave the last acknowledged site cached for restart recovery; an interrupted request fails visibly rather than being silently replayed. Revision conflict engine errors map to HTTP 409.

`app/service.py` serializes mutating operations and project/publication actions through an action lock. Rust owns the site and history. The Python service persists acknowledged autosaves in SQLite and restores the last site at startup. Undo history is process-local and is not serialized into `.fweb` files. New/imported sites clear the current saved-project identity. Existing projects are reopened by their stored site and subsequent save updates that project.

`app/store.py` uses the local ignored `backend/data` directory for SQLite, native files, export ZIPs and immutable publication snapshots. WAL is enabled. `.fweb` files carry `{format:"com.nodemode.formweb",version:1,site}`. Native saved files are atomically replaced; publication versions are new directories and never overwritten. Export paths reject absolute paths, traversal, backslashes, drive separators and null bytes.

### Checkpoint and project durability

The native checkpoint is `{schemaVersion:1,site,revision,undo,redo}`. Every acknowledged operation captures a complete validated Rust checkpoint. Startup and subprocess crash recovery restore the exact last acknowledged revision and complete history. Explicit project opening restores history while advancing the active revision. Invalid checkpoint documents and cross-site history are rejected atomically by Rust.

Main project mutations automatically update that named project's SQLite site/checkpoint without changing its display name. Active branch mutations automatically update only that branch snapshot and checkpoint. Switching projects or branches therefore retains acknowledged edits and undo/redo without requiring a second Save. Explicit Save also writes the portable `.fweb` file; current and project-ID download endpoints generate the latest corresponding acknowledged document/checkpoint. The on-disk path returned by explicit Save remains that explicit portable snapshot until the next explicit Save.

Portable native files now include the complete checkpoint and the union of owned raster assets referenced by current, undo and redo documents. This prevents undo from restoring a missing image after import into a fresh runtime data directory. Native envelopes and HTTP/MCP transport bodies are bounded at 64 MiB, history at 100 entries per direction and 32 MiB, current native sites at 8 MiB, individual rasters at 8 MiB and embedded asset count at 500. Legacy envelopes without checkpoint or assets remain accepted. Extra images restored before an invalid model rejection can remain as inert local digest files; the active model is unchanged.

Deleting a project requires management permission, removes its saved document/checkpoint, branches, branch checkpoints, comments, presence and grants. Frozen published versions and attributed historical activity remain independent release/audit records. If a named owner deletes the active project, its identity owns the fresh workspace; other identities receive no implicit access to it.

### Collaboration and attribution

Configured `FORMWEB_AUTH_TOKEN` is required before editor identities can be created. With authentication unconfigured, the local owner mode cannot claim enforced separate user roles. If identities already exist and root authentication is removed, dropping Authorization fails closed. Identity bearer tokens are revealed once and stored only as hashes. Browser control API/SSE cookies are random per identity, HttpOnly, SameSite Strict, process-bound and expire after twelve hours. MCP always requires the corresponding bearer identity and ignores browser cookies.

Roles are `viewer`, `reviewer`, `editor`, `publisher` and `owner`, with read/comment/review/edit/publish/manage permissions. The same service checks guard HTTP and official SDK tool/resource operations. Each MCP callback derives its actor from `ServerRequestContext.request.headers`; it does not inherit the manager's startup ContextVar identity. Presence lasts one minute unless refreshed. Comments retain the authored node ID through reorder and serialize author identity/name. Activity records accepted operations with the same REST/MCP actor.

Branches store base/current branch snapshots separately from main. Saving an open branch never overwrites main. Review requires main to be open and returns changes, current revision and conflicts with escaped JSON pointers. Dictionaries merge recursively; differing arrays are atomic conflicts. Merges require explicit `current` or `branch` choices for every conflict and can require `expectedRevision`; Rust records the merged site as one undo entry. Revision conflicts return HTTP 409 or an MCP execution error with status 409. A caller can read the fresh state and explicitly retry; no conflicting mutation is silently replayed.

SSE queues carry the affected project ID, coalesce slow subscribers and recheck current authentication/project permission before delivering state or keepalive. Revoked access emits an access-denied event and closes the stream. Browser cookies authenticate SSE without putting bearer tokens into query strings.

### Forms, inbox and delivery

Frozen publication and immutable preview forms validate their own saved document, not a later draft. Public default form endpoints are usable by visitors; a form reachable only through gated pages requires a matching visitor membership. Editor bearer identities do not substitute for website visitor identities. A shared form reachable from a public page remains public.

`extensions.forms.forms` configures success/error messages, success redirect, tracking query fields and per-field constraints. Intake returns field-specific `errors` with HTTP 422; typed outputs include finite numbers, checkbox booleans and bounded multiple-choice arrays. Required flags, email, URL, ISO dates, numeric bounds/step, radio/select choices, repeated-field cardinality, min/max lengths and a restricted regular-expression subset are checked. Patterns exclude groups, alternation, backreferences and more than one unbounded quantifier. Files are unsupported. Bodies are bounded at 64 KiB, field count at 128, values at 4096 characters, and IP requests at twelve per minute; the honeypot rejects automated entries before storage.

Inbox and CSV reads filter by permitted site IDs. CSV prefixes formula-like cells and carries typed values and declared tracking fields. Retention is persisted per site or for the root owner's global policy, applies at startup and every minute, and removes submission metadata plus corresponding durable delivery jobs and attempts. An already-initiated outbound network request cannot be recalled by deletion.

Webhook configuration contains approved endpoint URLs and `secretEnv` references, never inline secrets. `FORMWEB_WEBHOOK_HOSTS` is an exact host allowlist; production transport requires HTTPS/TLS on port 443, pins the approved resolved address and preserves hostname TLS validation. Explicit `FORMWEB_ALLOW_LOCAL_WEBHOOKS=1` exists only for loopback diagnostics. `FORMWEB_WEBHOOK_SECRET` is an example signing reference. Jobs survive restart, deduplicate submission/endpoint pairs, retain bounded attempt history and retry at most eight times with capped backoff. Terminal client errors exclude retryable 408/429. Signatures cover timestamp, job ID and the exact JSON body. Accepted locally stored submissions report queued or unavailable delivery honestly; no email delivery is claimed.

### Frozen releases and compiled preview privacy

Promotion and rollback move the active pointer to existing frozen files without rebuilding or mutating them. Native redirect maps accept legacy string targets (301) or exact `{to,status}` records with 301/302/307/308; frozen legacy list manifests remain supported. Native cycles, invalid status, normalized duplicate sources and self redirects reject atomically; a malformed frozen cycle returns 409. Frozen, active and preview redirects retain their package prefix. Active and version-qualified paths normalize directory indexes and resolve localized/CMS aliases through `routes.json` before membership authorization. Preview URLs select the exact compiled page/locale manifest entry and confirm its bytes exist before reporting success. Publication URLs use the manifest's real default-locale entry; root paths without index bytes redirect to that entry, and promotion validates those actual frozen bytes instead of requiring a root index file.

Compiled previews carry a one-hour nonce bound to immutable document/files. Their iframes have opaque origins and permit scripts/forms without same-origin access. `Origin:null` is allowed only for a verified nonce-bound preview/public runtime path, never editor APIs or MCP. Preview visitor/consent continuity uses nonce-bound `X-FormWeb-Visitor` and `X-FormWeb-Consent` tokens with credential omission; published visitor sessions use a separate HttpOnly cookie. Referrers are suppressed. Code component assets receive a response CSP sandbox with scripts permitted and network forbidden, including direct URL navigation.

Protected local publications omit the editable graph. Portable static export rejects sites with membership gates instead of exporting private content behind client-side hiding. Generic source-free `assets/runtime.js` and `assets/site.css` remain public. `asset-access.json` records compiler-derived code/CSS page ownership; Python unions owned raster references from actual rendered route HTML/page CSS. An asset with any public owning page is public. Otherwise at least one actual owning page must authorize the visitor; assets without ownership deny access when gates exist. Private route CSS, media and code are served with `private, no-store`.

### app/library.py

### app/library_routes.py

Every write builds its commands from the state it read and sends one `studio.mutate('batch', ...)` with that `expectedRevision`, so a concurrent edit fails rather than merging silently, and each action is one undo step. Bundled media and component posters are ingested with `application/octet-stream` and owned before the batch.
