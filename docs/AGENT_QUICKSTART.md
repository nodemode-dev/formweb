# FormWeb harness quick start

The [FormWeb harness](../.claude/skills/formweb-harness/SKILL.md) teaches a connected agent how to inspect the open website, apply validated changes, verify its consuming behavior and return editable/exported deliverables. The MCP server supplies actual operations; the skill supplies sequencing and recovery.

## Connect the pair

1. Install/build FormWeb using the repository launcher's current instructions, then start the backend. Keep the service running while the stdio proxy is connected.
2. Enable Agents within your authorized project scope, using the editor switch or the documented `FORMWEB_AGENTS` setting when the engine starts. Once it is running, only the FormWeb window can change the switch or the approval choices: an outside agent asks the person and waits. Configuration alone does not prove the server is connected.
3. Use the committed project MCP configuration. Unix clients run `./formweb mcp`; Windows clients use `formweb.bat mcp`. The proxy reaches the same Rust document as the editor. A client may instead use the documented SDK Streamable HTTP endpoint.
4. Install or enable the project skill in the intended client. The repository's `.agents/skills` mirror carries the same pack bytes; a standalone package must be installed separately on another surface. Run `./formweb agents sync --check` to compare project copies.
5. Inspect the client's connected status and live tool discovery. Authenticate using the configured server/identity policy without printing bearer tokens or provider secrets.

## First tasks

Start with: "In FormWeb, inspect the current site, change the hero headline, audit it, and save an editable project."

For a complete site: "In FormWeb, keep my existing footer. Build a responsive studio landing page, inspect it at 1280 and 390 pixels, save `.fweb`, and export the site."

For advanced work: "In FormWeb, inspect the available authoring and service tools. Review my CMS/component changes, retain approved content across conflicts, and report only the runtime and provider behavior you actually observe."

Advanced commands and provider operations are available only when the live server exposes them. Read its schemas before use. Rust batches use the current `expected_revision` supplied by a fresh `get_site` read. Service/provider tools may name revision arguments differently; preserve their exact discovered spelling.

A saved extension is configuration evidence. A browser interaction needs observed behavior. A local publication needs a returned local URL/version. A provider fixture proves transport, while actual hosting, domain/TLS/CDN or vendor sandbox checkout requires its own output and independent observations.

## Site-wide recipes

| Goal | MCP call | Check |
| --- | --- | --- |
| Site icon | Upload the square PNG (editor or `POST /api/assets`), then `apply_commands` with `site.update` `{patch:{settings:{favicon:"/api/assets/<id>"}}}`; `faviconDark` adds a dark-scheme icon | Exported `index.html` has `rel="icon"`, `apple-touch-icon` and `rel="manifest"`; the ZIP holds `site.webmanifest` and the icon |
| Page background | `apply_commands` with `node.update` `{id:<page root>, patch:{styles:{background:"#1d3557"}}}` (a `var(--token)` works too); `null` clears it. For every page, one batch with one `node.update` per page root (one undo step). A page with no background is white, the browser default, in the editor and in the export | `get_state` shows the root's `styles.background`; the exported `site.css` has it on `[data-fw-node="<root>"]` |
| Many pages from data | Put `{{column}}` tokens in a template page, then `page.bulk` `{template, rows:[{slug, name?, values}]}` (1 to 300 rows, one undo step) | Page count grew by the row count; sample pages show values, not tokens |
| Embed media | `node.add` a `div` with attribute `data-fw-embed` set to a YouTube, Vimeo, Loom, Spotify, Google Maps embed or OpenStreetMap embed URL, or an X post (`https://x.com/[user]/status/[id]`) | Preview or export shows `iframe[data-fw-embed-frame]`; an unsupported URL renders a visible `fw-embed-error` note |
| Load embeds on click | Site-wide: `site.update` `{patch:{settings:{embedClickToLoad:"true"}}}`; one embed: attribute `data-fw-embed-load` set to `click`. X posts are always click-to-load | Export shows `[data-fw-embed-gate]` with a Load button and an "Open on ..." link and no iframe until the visitor presses Load |
| Custom head and body code | Read the `code` group first, then `apply_commands` with `extension.set` `{group:"code", value:{...existing, siteCode:{head?, bodyStart?, bodyEnd?}, pageCode:{<pageId>:{head?, bodyStart?, bodyEnd?}}}}`; each slot up to 50,000 bytes. The group is replaced whole, so keep `components` and `instances` | Exported pages carry site code then page code before `</head>`, after `<body>` and before `</body>`; nothing runs on the canvas |
| Scroll and pointer effects | `node.update` `{id, patch:{attrs:{"data-fw-effect": "parallax"\|"scroll"\|"mouse"\|"marquee"\|"cursor", "data-fw-effect-speed": "0.5"}}}`; `null` clears either | Preview or export moves the element (translate, scale, opacity); with reduced motion nothing moves |
| Start an empty site | `POST /api/new` `{name, blank: true}` gives one Home page with an empty root (no sample content); then add pages and sections in one `apply_commands` batch | State has one page and one node until the batch runs; one undo after the batch returns to the empty site |
| QR code | `qr_code` `{url, dark?, light?}` returns SVG text; `GET /api/qr?url=...&format=png` returns a PNG | Decode it, or compare the returned `url` |
| Remove a photo's background | `remove_background` `{node, method?, feather?}` on an `img` with an uploaded picture; `action: "status"` checks formvis, `"restore"` returns the original | The image `src` is a new PNG and `data-fw-original-src` holds the original; the export shows only the cut-out |
| Add an icon or a stock photo | `search_stock` `{source: "icons"\|"formlit", query}`, then `insert_stock` `{source, id, parent?}`; icons take `color`, `stroke`, `size` | A new `img` under `parent`; the asset's credit is listed in the export's `CREDITS.txt`; respect any `usage` terms returned for a photo |
| Generate a picture | `generate_image` `{action: "generators"}` to see what formvis has set up, then `{prompt, generator?, size?, count?, insert?, alt?, parent?}`; waits up to 90 s, else returns `job` to pass back | Assets carry `prompt`, `generator`, licence and time in their credit; give `alt` that describes the picture, not the prompt |
| Edit a picture in formvis | `edit_in_formvis` `{node, action: "send"}`, the person (or formvis's own tools) edits, then `{node, action: "update"}` | The element's `src` changes to the edited PNG in one undo step; the credit gains `editedIn` |
| Rewrite an element's text | `write_copy` `{node, action: rewrite\|shorten\|lengthen\|tone\|generate, tone?, brief?}` returns `suggestion` and `apply` | Nothing changes until you run `apply` (one `node.update`); show the suggestion first |
| Draft pages from a description | `generate_site` `{action: "plan", prompt, pages?, references?}`, show the outline, then `{action: "build", plan}` | New pages with headers, sections, cards, buttons and contact forms in one undo step; slugs never collide; existing pages are untouched |
| Use a reference or revise the outline | `generate_site` `{action: "reference", asset}` or `{action: "reference", name, data}` (base64 PDF or image); `{action: "plan", prompt, plan, instruction}` revises | A PDF returns `text` (facts for the model), an image `colors` (button colour after any brand kit); a revised plan has `mode: "revised"`, a failed one leaves the outline as it was |

## Reading and editing efficiently

Read `formweb://site/tree` first: every page as an outline of element IDs, tags, names and text, a few KB instead of the whole document. `formweb://selection` is what the person has selected in the editor ("make this bigger"). `get_site` with `detail: "summary"` returns pages, components, collections and settings; `detail: "full"` (the default) returns every style. Make single changes with the `edit_*` domain tools, which list their commands' parameters, and multi-command changes with `apply_commands`. Both return a compact summary; pass `detail: "site"` only when you need the whole document. Failed calls include a `next` field saying what to do. In Claude Code, `@formweb:formweb://site/tree` attaches the outline to a prompt.

| Goal | Tool | Notes |
| --- | --- | --- |
| Use or extend the brand kit | `formweb://tokens` key `brand`; `edit_styles` `token.define` `brand-[name]` (color) or `brand-font-[name]` (text); logos in settings `brandLogo`, `brandLogoDark` | Style with `var(--brand-[name])` so changes follow the kit |
| Check a page against the brand | `brand_check` `{page?}` returns off-brand colors, fonts and logos, each with a ready `fix` command | Pass the `fix` values to `apply_commands` as one batch; a second `brand_check` returns no issues |
| Restrict styling to the brand | `site.update` `{patch:{settings:{brandRestrict:"true"}}}` (needs the manage permission) | The editor then accepts only `var(--brand-...)`, `var(--lib-...)` or neutral values in color and font fields; `brand_check` still reports agent edits |
| Use the team's shared library | `list_team_libraries`, then `use_team_library` `{id, action:"link"}`; `"sync"` when `updateAvailable` is true | The site gains `lib-[library]-[name]` tokens; style with `var(--lib-...)` |
| Change or share a team library | `save_team_library` (no `id` creates; `from_brand: true` copies this site's kit; pass `expected_revision` when changing), `share_team_library` `{id, identity_id, role}` | `list_team_libraries` `{id}` shows the new revision and members |
| Password-protect a page or folder | `set_page_password` `{route, password}`; `null` removes | Enforced when FormWeb serves the published site; export is refused while set; never echo the password |

## Terminal and CLI

Inside the editor's terminal (or any shell in the FormWeb folder) `./formweb run --list` lists engine commands and `./formweb run COMMAND key=value ...` applies one, for example `./formweb run node.update id=headline 'patch={"text":"Hello"}'`. Values are parsed as JSON when they can be; add `--json` for machine output and `--revision N` to require a revision. The command line is an outside agent like any other: it calls the MCP endpoint, so Agents must be on and the approval settings apply. The change appears on the open canvas at once, is one undo step, and shows as `agent` in Agent Connect's activity feed. The terminal's preset menu starts `claude`, `codex` or `cursor-agent` in the same folder, so those clients pick up the project MCP files.

If a call waits and then reports that no one approved it, the owner has turned on approvals in Agent Connect; ask them to watch the panel and retry once.

Editor ids for the same actions: `site.favicon`, `site.favicon-dark`, `site.favicon-clear`, `page.bulk`, `insert.embed`, `page.qr`, `brand.check`, `brand.fix-all`, `brand.restrict`, `window.team`, `image.remove-background`, `insert.stock`, `image.edit-in-formvis`, `image.update-from-formvis`, `page.generate`, `ai.suggest`, `ai.accept`, `ai.site-reference`, `ai.site-revise`, `page.background`, `page.background-clear`, `page.background-all`, `window.theme-colors`.

## Creative, CMS and vector commands (v0.7)

These engine commands go through `apply_commands` or the `edit_cms` and `edit_creative` domain tools, which print each command's parameters. `./formweb run --list` shows the same catalogue.

| Goal | Command | Arguments | Check |
| --- | --- | --- | --- |
| Filters, sorting or a slider on a collection list | `cms.list` | `{node, patch:{facets?, sortOptions?, slider?, pageSize?, filter?, sort?, limit?}}`; `facets` `[{key, field, kind: checkbox\|select\|search\|range, label}]`, `sortOptions` `[{key, field, direction, label}]`, `slider` `{perView, arrows, dots, autoplay, interval, loop, label, gap}` (not combinable with facets); null removes a key | The published list shows live controls and keeps their state in the URL |
| Slider of collection cards | `slider.create` | `{parent, collection, perView?, index?}` | A slide card bound to the collection plus its slider list config |
| Table | `table.insert` | `{parent, rows?, cols?, header?, caption?, index?}` | Semantic table with caption, `thead` with `th scope="col"` and `tbody` |
| Table rows and columns | `table.row.add`, `table.row.remove`, `table.col.add`, `table.col.remove` | `{table, index?}` to add (before that index, else at the end), `{table, index}` to remove; columns need a regular table without merged cells | Row and cell counts match |
| Collection folders | `cms.folder` | `{id, name?, collections?:[collectionId], remove?}`; a collection lives in one folder | Folder lists its collections |
| Manual item order | `cms.reorder`, `cms.move` | `{collection, ids:[itemId]}` (every item once), `{collection, id, index}` | List order follows the new order |
| Superscript and subscript | `text.script` | `{id, mode?: super\|sub\|none\|keep, shift?: "-0.2em"\|null, trueGlyphs?}` | The span is a real `sup` or `sub` with a baseline shift |
| Multi-step form | `form.steps` | `{form, steps:[{title, nodes:[childId]}]}` groups direct children of the form; `steps: []` removes them | Export has Back, Next and per-step validation |
| Layout with site defaults | `layout.convert` | `{id, mode: flex\|grid, direction?, columns?, gap?, padding?}`; omitted values come from the site settings `layoutGap`, `layoutPadding` and `layoutColumns` | The element's display, gap and padding follow the defaults |

Vector authoring uses ordinary `node.add` and `node.update` with svg tags. An inline vector is an `svg` node (attrs `viewBox`, optional `preserveAspectRatio`, `width`, `height`; styles position absolute, left, top, overflow visible) holding `path` nodes with `d` and the paint attributes (`fill`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, `fill-rule`, `opacity`, `transform` and the rest the engine allows). An agent can write `d` alone: the editor re-reads the shape from `d` when it disagrees with its own anchor model (`data-fw-vector`, which export drops). Beyond `svg` and `path`, the engine accepts `g`, `defs`, `linearGradient`, `radialGradient`, `stop`, `clipPath`, `mask`, `text` and `textPath`. Gradient, clip and mask references are only `url(#id)` on `fill`, `stroke`, `clip-path` and `mask`, and only to an id defined in the same `svg`; anything else (scripts, other `url(` values, event attributes) is rejected and leaves the document unchanged. The inspector's tag field shows `svg` and `path` read-only. Check that the exported HTML holds the `svg` and, for gradients, the `linearGradient` or `radialGradient` definition. `POST /api/vector/import-svg` cleans an SVG with the same allowlist.

Vector selection commands run through `run_ui_command` while the vector editor is open: tools `vector.lasso` (Q), `vector.wand` (Y) and `vector.eyedropper` (I) are pointer tools, and `vector.select.same-fill`, `vector.select.same-stroke`, `vector.select.same-weight`, `vector.select.same-opacity`, `vector.select.same-fill-stroke` and `vector.select.inverse` change the selection by the first selected shape's look. `vector.transform-again` (Ctrl+D) repeats the last transform and is the only one of these that edits the site; it is available while a vector tool is active.

Warp and global editing (v0.9.2), run with `window.formweb.run(id)` while a shape is selected: `vector.puppet` (Pin Warp tool: pins, moving-least-squares bend of the selected paths), `vector.reshape` (Reshape tool: drag a selected anchor to move the other selected anchors in proportion, or drag a segment to add and pull an anchor) and `vector.global-edit` (Start or Stop Global Edit: shapes whose geometry matches the selected one up to translation are highlighted and receive the same paint and geometry edits in one undo step; Escape stops). None has a default shortcut.

Tweak and objects on a path (v0.9.3): `vector.effect.tweak` opens Tweak (random horizontal and vertical moves, relative to the path size or absolute, for anchor points and the "In" and "Out" control points, with a seed and Preview; OK is one undo step). `vector.path.objects-on-path` places the selected shapes along the shape selected last: first at the start, last at the end of an open path (evenly around a closed one), each centered on the path and rotated to its direction, in one undo step; it is not live.

Blob Brush (v0.9.4): `vector.blob-brush` (Shift+B) selects the tool. Each drag paints a filled, unstroked shape the width of the brush in the stroke color (the fill color when stroke is none) and unites it with overlapping unstroked paths of the same fill in the edited SVG, one undo step per stroke. Double-click the canvas with the tool active for Size, Fidelity, Keep Selected and Merge Only with Selection; `[` and `]` change the size.

Fill Regions Bucket (v0.9.5): `vector.live-paint-bucket` selects the tool (no default key; K is the Knife). Select two or more overlapping paths first; the face under the pointer is highlighted, a click adds it as a fill-only path in the current fill color under the selected paths (or recolors a face painted before), and Shift-click sets the stroke of the clicked path. One undo step per click. Since v0.11.5 the click makes a live group instead (`vector.livepaint.make`, `.expand`, `.release`): the group carries `data-fw-livepaint` {v, src, fills: [signature, x, y, colour], of, sig}, where the signature is the bitmask of sources covering a face in paint order, and the editor redraws the faces whenever the sources change. Since v0.11.8 the spec may also hold `edges` ([source index, signature of the other sources beside the edge, x, y, colour, width], drawn as stroke-only paths after the faces) and `os` (each source's original "stroke width"); once `edges` is present the sources' own strokes are none and Release restores them from `os`, while Expand (v0.11.9) removes the sources and keeps only the face and edge paths.

OpenType features (v0.9.6): node styles accept `font-variant-ligatures` (for example `discretionary-ligatures`, `no-common-ligatures`), `font-variant-caps` (`small-caps`, `all-small-caps`, `petite-caps`, `unicase`, `titling-caps`), `font-variant-numeric` (combine `lining-nums` or `oldstyle-nums`, `proportional-nums` or `tabular-nums`, `diagonal-fractions` or `stacked-fractions`, `ordinal`, `slashed-zero`) and `font-kerning` (`auto`, `normal`, `none`), set with `node.update` styles like any other property and exported as CSS. The Typography section shows them as Capitals, Kerning, Ligatures and Numbers.

Patterns (v0.9.7): `vector.pattern.make` opens Pattern Options for the current selection; the last selected shape is filled and the other selected shapes become the tile (Grid, Brick by Row or Brick by Column, brick offset 1/4 to 4/5, Size Tile to Art with H and V spacing, or a fixed width and height). It adds a `pattern` element with `patternUnits="userSpaceOnUse"` inside the svg and sets `fill="url(#pattern-...)"`, one undo step. Through `node.add` an agent can build the same structure: a `pattern` under the svg (attributes x, y, width, height, patternUnits, patternTransform; children `g` and `path`; no `href`). Area type texts placed since v0.11.2 carry `data-fw-area` {v, src, text, leading, align, inset, columns, gutter} and reflow when an editor commit changes the source path's `d`; a change made only through the API does not reflow them. `vector.type.area-edit` (v0.11.3) reopens the dialog for selected area type, or its shape, and updates the words and settings in place; a person can also double-click area type to type on the canvas (v0.12.0), which writes the same `text` field. `vector.type.thread` (v0.11.4) links the area type to more selected closed shapes: the spec gains `chain` ([shape id, text id] pairs) and `over` (words left after the last shape); `vector.type.thread-release` rolls the words back into the first shape. `vector.type.thread-remove` (v0.11.6) ends the thread but keeps every word where it is: each linked text gets its own `data-fw-area` with the words it shows (the last one keeping `over`), and the first loses `chain`. `vector.type.thread-release-selection` (v0.11.7) takes the selected shapes out of their thread (outlines kept, texts removed); if the first shape is selected, the next linked text becomes the one carrying `data-fw-area`, so look the spec up again afterwards. The in and out ports drawn on selected area type are editor gestures only; through the API, link a shape by writing `chain` and laying the lines out yourself, or use `vector.type.thread`. Since v0.11.1 the tile types include Hex by Column and Hex by Row, the options are stored on the pattern as `data-fw-pattern` ({v, tile, offset, sizeToArt, width, height, hSpace, vSpace}), and `vector.pattern.edit` reopens them for the selected shape's pattern and rebuilds its tiles under the same id.

Area type (v0.9.9): `vector.type.area` opens Area Type for the selected closed shape (text, font size, leading, family, weight, color, alignment, inset spacing, columns, gutter) and flows the words inside it as one `text` with a `tspan` per line, placed after the shape; leftover words are reported as overflow. Laid out once; run it again after reshaping. Agents can write the same structure directly: a `text` with `tspan` children (attributes x, y, dx, dy; plain text up to 500 characters each; no children).

Artboards (v0.10.1): every `svg` on a page is an artboard. `vector.artboards` toggles the Artboards panel in the open window (rename, select, duplicate, fit to artwork, resize, delete, new artboard from a preset). Agents do the same with engine commands: a new artboard is a `node.add` of an `svg` with `viewBox`, `width`, `height` and absolute `left`/`top` styles; fitting changes `viewBox`, `width`, `height` and `left`/`top` together so the art keeps its place. Export for Screens (`vector.export-screens`) has a third scope, All artboards on this page, which downloads each artboard of the current page under its own name with the file name field as a prefix (v0.10.2). `vector.artboard-tool` (Shift+O, v0.10.3) selects the Artboard tool: a drag on empty canvas draws a new artboard under the page root, a drag inside an artboard moves it, and the eight handles on the selected artboard resize it without moving its art (v0.10.4). Shift-click adds artboards to the selection and a drag moves them all (v0.10.8); Shift-drag on empty canvas selects every artboard it touches, and arrow keys nudge the selection by 1 or 10 px (v0.10.9); `vector.artboards.rearrange` opens Rearrange All Artboards (Grid by Row or Column, Arrange by Row or Column, spacing, left to right or right to left) and the panel rows have Move up and Move down, which reorder the `svg` nodes under their parent (v0.11.0); agents move several artboards with one batch of `node.update` commands on their `left` and `top` styles.

Freeform gradients (v0.10.6): `vector.gradient.freeform` (or Freeform in the Gradient panel) wraps the selected path in a group with `data-fw-freeform` {v, src, grads, pts, cols, sig}: `pts` are [x, y, spread] in the path's bounding box (0 to 1, spread 0.02 to 1), `cols` are hex colours, `grads` name one `radialGradient` per stop in the svg. The editor draws each stop as a layer path filled with its gradient and keeps them in step when the stops or the source path change. Agents edit stops in the editor with the Gradient tool, or change the spec or the source path through the API, and an open editor refreshes the layers when it sees the change (a source edit through `/api/batch` was refreshed this way in v0.10.6); the model refuses the attribute on anything but a group whose `src` is a path inside it. Lines mode (v0.10.7) adds two optional keys: `ln`, a line number per stop (0 for a free point; stops sharing a number are joined in list order), and `sg`, one `radialGradient` per interpolated sample along the lines (one per 0.05 of the box, at most 12 a segment and 160 in all). The editor creates the sample gradients when it writes stops; an agent writing `ln` itself must also supply matching `sg` gradients.

Path commands and drawing tools (v0.9.1), run with `window.formweb.run(id)`: `vector.path.add-anchors` (midpoint of every segment of the selected paths), `vector.path.remove-anchors` (selected anchors), `vector.path.divide-below` (selected path cuts the filled shapes beneath it), `vector.path.split-grid` and `vector.path.clean-up` (dialogs), and the tools `vector.pencil` (N), `vector.arc`, `vector.rect-grid` and `vector.polar-grid` (the last three have no default shortcut).

## Editor window commands (v0.7)

Three MCP tools reach the open editor window, which must be open in a browser or the desktop app: `list_ui_commands` `{query?}` lists the window's commands (id, label, keys, group, `mutates`, `risky`, availability; words in `query` must all appear in the id, label, group or description), `describe_ui_command` `{id}` returns the description, shortcut, parameters and current availability, and `run_ui_command` `{id, params?}` runs one as if the person used its menu item or shortcut and returns what it returned or why it did not run. They are window actions: change the site with `edit_*` and `apply_commands`. A risky command waits for the person to press Allow in the window (Deny, or no answer in 45 seconds, refuses). An unknown id returns 404 and no open window returns 409. The same list is on `GET /api/commands?q=` and a command runs on `POST /api/commands/run {id, params}`.

Vector view aids (run with `run_ui_command` while vector editing): `vector.rulers` (Mod+R), `vector.guides.toggle` (Mod+;), `vector.guides.lock` (Mod+Alt+;), `vector.guides.make` (Mod+5), `vector.guides.release` (Mod+Alt+5), `vector.guides.clear`, `vector.grid.show` (Mod+'), `vector.grid.snap` (Mod+Shift+'), `vector.grid.prefs` and `vector.outline` (Mod+Y). Guides are saved on the SVG as `data-fw-guides` (numbers only, up to 200, plus a locked flag); creating, moving, deleting, making, releasing, clearing and locking guides is one undo step each, and the attribute is dropped from exports. Outline mode only restyles the canvas. `vector.export-screens` (Mod+Alt+E) opens Export for Screens: PNG, JPG, WebP and clean SVG of the edited SVG or the selection at 0.5x to 4x, and (v0.12.4) a one-page vector PDF at 1x (paths, clips, opacity, symbols and text in Helvetica; gradients fall back to their first stop; images, masks and filters are left out), downloaded from the browser. `vector.snap.toggle` (Mod+Shift+;) switches smart guides; `vector.snap.pixel` (v0.12.3) switches Snap to pixel grid, off by default; holding Control while drawing or dragging suspends snapping. `vector.mask.use` (v0.12.2) is Figma's Use as mask: the bottom selected path clips the paths above it, and running it on masked content removes the mask. Symbols (`vector.symbol.define`, `vector.symbol.break`) are shared across the drawings on a page since v0.12.5 and across the whole site since v0.12.6: a `use` may point at a `symbol` in any svg on any page (the canvas and the exporter copy symbols from other pages into a hidden svg on the page that uses them), and the engine refuses a change that would leave an instance pointing at a deleted symbol, so detach instances first.

Recolor and styles (v0.9.2), run with `window.formweb.run(id)`: `vector.recolor` (Edit menu, no shortcut) opens the Recolor Artwork dialog for the selected shapes or the whole edited SVG, with live preview and one undo step on OK; `vector.graphic-styles` (Window menu, no shortcut) opens the Graphic Styles window. The style library is the site setting `vectorGraphicStyles` (a JSON list, validated by the engine, shared by all SVGs, not exported).

## Recover a stopped workflow

For missing tools, rediscover instead of guessing names. For permission rejection, inspect actual identity/role and Agents state. For a stale revision, read current state, preserve acknowledged changes and apply only the remaining change with a fresh revision. Do not replay successful steps.

Call a failed tool directly using its actual schema to separate server/transport/access failures from sequencing mistakes. Keep credentials on the server and report presence or missing environment names only. Preserve unsaved work before opening a different project or branch.

The pack's [scenario evaluations](../.claude/skills/formweb-harness/references/evaluations.md) and [trigger cases](../.claude/skills/formweb-harness/references/trigger-cases.md) are specifications. The release audit records actual executions. Their existence does not prove automatic skill activation, browser coverage or a reduction in calls.

## Driving the editor window

Every menu action has a stable command id (`file.save`, `edit.undo`, `insert.heading`, `view.mobile`, `window.studio` and so on). In the browser, `window.formweb.commands()` lists them with label, menu, shortcut and whether each is enabled right now, and `window.formweb.run(id)` runs one exactly as the menu would, returning false when it is disabled. Menu rows and command-search results carry the id in `data-command`. People reach the same actions from the menubar or with Ctrl/Cmd+K. Prefer MCP for site changes; use these ids (or `list_ui_commands` and `run_ui_command`) when an agent has to operate the window itself (switching breakpoint, opening a panel or dialog). Agent ids: `window.agents` (Agent Connect panel), `agents.toggle` (MCP and terminal on or off), `view.terminal` (Ctrl+`), `terminal.new`; panel buttons carry `agents.client.<id>`, `agents.launch.<id>`, `approvals.approve` and `approvals.deny`. `file.home` (File > Home, Alt+Ctrl/Cmd+H) shows the Home screen over the editor. Demo ids (Help > Demos, also the demo cards on Home): `demo.lowlight`, `demo.looking-back`, `demo.harbour-ferries` and the five whole-site starters `demo.coldmere-plumbing` (business), `demo.northfold-studio` (portfolio), `demo.slow-allotment` (blog), `demo.wenlow-type-day` (event) and `demo.fernhollow-pottery` (shop) each open that demo as a new, unsaved site; they replace the open site, and the window asks the person first when that site has changes not saved as a project. `demo.preview` (optional `id`: any of the eight demo ids) shows a finished demo in a preview over the window and changes nothing, and `demo.preview-close` closes it; while the preview is open every command except the `demo.` ids is disabled, and running one of the eight open ids closes the preview first. Layout ids: `window.toggle-left`, `window.toggle-right`, `window.toggle-rail` and the presets `workspace.design`, `workspace.content`, `workspace.build`, `workspace.focus`; rail buttons and collapsed-panel strip buttons carry the same `data-command` ids. Pages and layers panel ids (0.29.0) take an optional `id` (the open page or the selected element when left out): `page.open` `{id}`, `page.rename` `{id?, name?}`, `page.duplicate`, `page.set-home`, `page.move-up`, `page.move-down` and `layer.rename` `{id?, name?}` change the site, one undo step each (without `name` a rename opens the name for the person to type); `layer.collapse-all` and `layer.expand-all` change only the layers list. `page.set-home` also points links and click actions at the page's old address to `/`, and refuses, with the reason in the status line, when either page is a CMS template or has a translated address, or a password protects the page through a route other than `/`. To reorder pages from MCP use the engine command `page.move {id, index}`.

Canvas context menu ids act on the selected element: `edit.text` starts inline text editing on the canvas, `edit.select-parent` selects the containing element, `edit.wrap` puts the element in a new empty div (one undo step), `style.copy` remembers its styles for the picked breakpoint in the window and `style.paste` applies them to the selection (one undo step), and `inspector.text-style`, `inspector.background`, `inspector.spacing`, `inspector.size`, `inspector.link` and `inspector.image` open the right panel at that field. From MCP, change styles with the engine command `node.update` instead.
