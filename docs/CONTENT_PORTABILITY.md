# CMS CSV and pinned libraries

GET /api/cms/[collection-id].csv exports every stored item, including drafts and archived items. Quoted commas and embedded newlines use CSV quoting. Control columns carry id, slug, status, _present, _nulls and _locales. Field columns use `field:[name]` so collection fields named id or slug cannot collide with item metadata. Presence and null lists preserve missing values, null and empty strings separately. Number, boolean and multiple-reference cells use JSON values. Localized item overrides are complete JSON in _locales.

POST /api/cms/[collection-id]/import receives csv and mode, either upsert or replace. Import also accepts unprefixed field names when they do not conflict with control columns. New rows without IDs receive stable IDs; status defaults to draft. Wrong columns, types, duplicate IDs/slugs and conflicts with stored slugs fail before any document change. Item replacement and locale overrides commit as one Rust-validated batch with a revision check. The limits are 10,000 rows and 8 MiB input. Replace removes omitted items; references to removed items must remain valid or the transaction fails.

GET /api/libraries lists immutable component-library versions. POST /api/libraries stores a named dotted version from the current site, an explicit Site, or a native FormWeb envelope. A library selects known components, bundles owned images and receives a digest. An existing ID/version cannot be overwritten. Nested library pins must be detached before creating another snapshot.

POST /api/libraries/[id]/import imports a selected version into a parent node through the Rust library.import command. GET /api/libraries/[id]/review?version=[version] reports added, removed and changed source components against the current pin. Updating an existing pin requires update:true and reviewDigest matching the selected version. This acknowledgement and the document revision protect the reviewed operation. Rust library.update propagates the accepted source change; library.detach retains local content while removing the pin.

Review compares component definitions as well as their selected nodes. A definition-only prop-default change appears as changed and materializes after an acknowledged update. Copied global tokens, breakpoints, locales and selected forms participate in the digest; changing those shared dependencies conservatively marks every selected component as changed.

Local library storage is a component sharing workflow across projects in this FormWeb service. An exported native snapshot also carries its owned images. It does not imply a proprietary vendor's cloud library service.

## Static sites from a zip

POST /api/library/import-site/review takes the bytes of a .zip holding a static site (HTML, CSS, JavaScript, pictures, fonts) and answers what an import would do without changing anything: each page with its file, proposed route and the route it would replace, the number and size of assets, every skipped file with a reason, the count of ignored system files, whether replacing matching routes is safe, and the revision it was computed against. POST /api/library/import-site?mode=new|replace&revision=N imports the same bytes as one Rust-validated batch, so one undo step, and refuses with 409 when the site has changed since that revision. File > Import site from zip... and the MCP tool library_import_site use these routes.

Each HTML file becomes a page holding one code section under the single-page Import HTML rules; it is editable as code. In the editor the import offers to bring pages in as editable elements, and any code section can be converted later (Convert to editable elements..., command `library.convert-section`); the section below says what that keeps. Pictures, videos and WOFF2 fonts are stored through the asset store with its type and size checks and their references rewritten; links between imported pages are rewritten to the new routes; external URLs are untouched; title and meta description fill page SEO. The archive is read in memory under hard caps (64 MiB archive, 1,000 entries, 2 MiB file list, 128 MiB unpacked, 12 folder levels, a 100 to 1 expansion limit for entries over 1 MiB, per-file caps matching the asset caps) and refused whole for absolute, drive-letter or `..` names, symbolic links and passwords. The import changes neither the site document model nor GET /api/export: an imported page exports like any page with a code section. [LIBRARY.md](LIBRARY.md) lists the exact rules.

Converting HTML to editable elements happens in the editor window, because it needs a browser to work out the cascade: the section's HTML and CSS are rendered in a hidden frame with no scripts and no outside network, each element's computed style is reduced to what differs from that element's own default, and the result goes to the engine as one batch of `node.add` commands with chosen ids (one undo step), so the engine's tag, attribute, URL and style allowlists are the last word. What converts: every tag the engine takes (structure, headings, text, inline formatting as child elements, links, pictures, lists, tables, forms and fields, figures, details, video and audio), with text, ids, link addresses and targets, picture sources, alternative text and sizes, form attributes and table spans; old presentational tags and attributes (`<font>`, `<center>`, `bgcolor`, `align`, `cellpadding`) become styles. Base styles only: layout (display, flex, grid, gaps, alignment, position), sizes, spacing, type (family, size, weight, style, line height, letter spacing, alignment, case, decoration), colours, background colours and gradients, borders, radius, shadows, opacity, overflow, object fit, list and table styles, transforms. Self-hosted WOFF2 faces the page uses join `design.fonts`. What stays as code, in place, as small code sections with their measured look inlined: scripts (the page script is kept unless the person unticks it), inline frames, `<svg>`, `<object>` and `<embed>`, `<canvas>` and custom elements. What is lost, and named in the result: `@media` rules (no breakpoint is created; redo small screens in the breakpoint list), `:hover` and `:focus` styles, `::before` and `::after` content, `url()` background pictures from other websites or tiled (the style allowlist takes no `url()`; an own-asset picture sized `cover` or `contain` instead becomes an `img` placed behind the content with `position: absolute`, `z-index: -1` and `object-fit`, its box given `isolation: isolate`), floats (no `float` property), event handlers and `javascript:` links, classes, and any value the engine refuses (counted). A page drawn by the browser in quirks or almost-standards mode (an old HTML 4 doctype) can differ by a few pixels of line height, since exported pages use standards mode. One section converts to at most 480 elements, and the pages of a site import convert together in one batch (up to the engine's 4,000 commands), a page too large for that staying a code section; a larger page converts one top-level part at a time, its remaining code scoped to its own element. The exported page and the canvas of a converted page draw the same at desktop width; the measured difference is in [Importing](guide/09-importing.md#how-close-the-result-is).
