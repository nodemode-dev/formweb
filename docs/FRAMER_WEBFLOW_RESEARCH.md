# FormWeb: researched Framer and Webflow capability catalog

Research date: 10 October 2026.

Fetched primary official documentation; no training-data claims. Common categories are cross-validated by independent Framer/Webflow documentation, while each vendor-specific implementation fact remains explicitly single-organization evidence. Unknown is not absence.

Each product-specific fact below is supported by that vendor alone and could not be independently corroborated. Both vendors document the common capability categories; that does not independently corroborate a particular vendor implementation. Source links point to fetched official pages. Source update context is included in the JSON registry. Unknown means not established by this research, not absent.

## Architectural implications (design judgment)

Use one Rust document engine for schema validation, stable IDs, structural edits, component expansion, responsive CSS compilation, CMS/locale materialization, diagnostics, and portable export. FastAPI should persist projects/content/submissions/releases and enforce the same permissions for REST and MCP. TypeScript/Vite should maintain stable mounted inspector/canvas controls and apply engine operations without replacing whole panels. Real MCP needs an independent client round trip; tool names alone are insufficient. Publishing should produce immutable release snapshots before promotion, with local/static publishing reported separately from managed hosting.

## Current-source corrections

- **Native Webflow User Accounts:** W23 sunset overrides retained User Accounts references in older W26 export docs; native memberships are retired.
- **Native Framer MCP versus agent connectivity:** F19 describes constructing MCP atop Server API; F23 documents native agent CLI which does not require manual MCP. Do not claim official Framer hosted MCP equivalence.
- **Webflow whole-site code export versus DevLink:** W26 site ZIP export and W27 React component export are different products with different functionality.

Webflow Localize explicitly does not support Ecommerce Site plan features together. [Source W15](https://help.webflow.com/hc/en-us/articles/33961240752147-Webflow-Localize-overview). This is Webflow-only evidence, not independently corroborated.

## Priorities

P0 is the local visual builder/CMS/forms/compiler/MCP/export foundation. P1 adds deeper design systems, relations, richer interactions, branches, comments, and external fetch. P2 requires larger runtime/infrastructure/provider work: shared presence, real managed domains/TLS/CDN, code components, machine translation, payment checkout, memberships, analytics and experiments. The priorities are implementation judgments, not vendor claims.
