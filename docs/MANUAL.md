# FormWeb manual

FormWeb is a visual website authoring application with editable pages, a node hierarchy, responsive styles, reusable components, CMS data, translations and static website export. The Rust engine owns the document; the editor and agents change that same document.

## Guide

New to FormWeb? The [user guide](guide/README.md) teaches the app step by step, in plain words, with a screenshot for every step and a worked example on one of the demo sites. Start with [Your first site](guide/01-first-site.md), which goes from an empty page to an exported zip. The task guides cover [pages and layers](guide/02-pages-and-layers.md), [working on the canvas](guide/03-canvas.md), [the right panel](guide/04-right-panel.md), [page background and theme colors](guide/05-background-and-theme-colors.md), [preview](guide/06-preview.md), [the audit](guide/07-audit.md), [export and publishing](guide/08-export-and-publish.md), [importing](guide/09-importing.md), [components and the Library](guide/10-components-and-library.md) and [keyboard shortcuts](guide/11-keyboard-shortcuts.md). [Coming from Dreamweaver or another visual builder](guide/12-coming-from-other-builders.md) maps familiar tools to FormWeb. In the app, Help > Using FormWeb starts with an Open the full guide button that opens the guide on GitHub in a new browser tab (in the desktop app, in your system browser). This manual is the full reference the guide links to.

## Start the editor

Install Node 22.12 or later, Python 3.12 and Rust stable. From the repository:

```bash
./formweb install
./formweb boot
```

On Windows use `formweb.bat install` and `formweb.bat boot`. The editor works in windows down to 760 x 640 (the desktop shell's window stops at 1024 x 680): menus that do not fit the menubar move into a More menus button (three dots) at its end, which lists them and opens each with the same commands and shortcuts, by mouse or keyboard; the top bar is one row from 800 px up in every language and two rows below, so switching the language never changes its height; Export and Audit show only their icons in a narrow toolbar, the stage header shortens its crumbs and readout with an ellipsis, the side panels narrow, and the inspector puts its tabs two by two and its fields in one column whenever they would not fit. Open http://localhost:5240. The API runs on http://127.0.0.1:8240. `./formweb doctor` lists missing tools or builds. To serve a built editor with one process, run `./formweb build`, then `./formweb serve`, and open the API address.

The default data folder is `backend/data`. Configure `FORMWEB_DATA_DIR` in `backend/.env` before launch to choose a persistent location. Keep a saved editable project or downloaded native document before replacing the checkout. Since 0.20.2, at start the backend removes its own temporary files in the data folder that are more than 10 minutes old (leftovers of a killed paste, load or save: `assets/.stage-*.part`, `tmp/project-*.fweb`, `tmp/load-*.fweb` and `projects/.pending-*`) and logs "Removed N stale temporary file(s) from the data folder." when any went. Only regular files with those exact names are removed; symlinks, directories, younger files, publication `.pending` folders and FormPublisher's inbox are left alone.

## Home and the demos

Home (File > Home, or the formweb mark in the top bar) opens over the editor. Its Start page shows recent sites, the Demos and the New site tiles; Recent and Projects list what you opened and saved. A new site started from Blank (Home's Blank site, or File > New site... with Start from set to Blank) has one empty Home page; the sample aster / studio page appears only when FormWeb first starts with no site to restore.

Eight finished demo sites come with the app: Lowlight (a studio site made from library sections, with scroll scenes and animated components), Looking Back (a photo essay told in pinned scroll scenes, with a filterable gallery and a lightbox), Harbour Ferries (a service site with a fare calculator, CMS route pages, site search and redirects), and five whole-site starters to begin a real site from:

- Coldmere Plumbing, a business and services site: home, services and prices, about, contact by phone and email, and a 404 page.
- Northfold Studio, a portfolio: home with selected work, a work list, project pages from a CMS collection, about, contact and a 404 page.
- The Slow Allotment, a blog: home with the three newest posts, a post archive, post pages from a CMS collection, about and a 404 page.
- Wenlow Type Day, a one-day event: home, programme, speakers from a CMS collection, venue and travel, tickets information without a checkout, and a 404 page.
- Fernhollow Pottery, a shop window: home, a product list, product pages from a CMS collection, about, how to order by email, and a 404 page; there is no checkout.

The starters share a header and a footer as linked components (Site header and Site footer), so a change to one shows on every page. Each has its site name, a description on every page, a site icon, a base URL, and a share picture named in the site's head code (the page inspector's Custom code section, for the whole site); change the base URL and that address together when you put the site on its own domain. None has a form: contact is an email link. Each demo folder also holds a `demo.json` with the demo's name, one-line description and site type (`business`, `portfolio`, `blog`, `event` or `shop`).

Each demo card on Home has two actions:

- The card opens the demo as a new, unsaved site, ready to edit. It replaces the open site and asks first when that site has changes that are not saved as a project. Saved projects are not changed; save the demo to keep what you change.
- Preview shows the finished site over the window, every page, working as a visitor would see it, without replacing the site you are working on. A bar inside the preview switches between the eight demos. The top row names the demo on show; Open this demo closes the preview and opens that demo for editing, and Close or Escape returns to where you were. While a picture is open in a demo's lightbox, Escape closes the picture first. Links to other websites open in the system browser.

Help > Demos is a submenu with the eight demos and Preview the demo sites. The same actions are the commands `demo.lowlight`, `demo.looking-back`, `demo.harbour-ferries`, `demo.coldmere-plumbing`, `demo.northfold-studio`, `demo.slow-allotment`, `demo.wenlow-type-day`, `demo.fernhollow-pottery` and `demo.preview` (`demo.preview-close` closes the preview). The pictures in the demos are credited in `frontend/public/demos/CREDITS.md` and in NOTICE.md.

## Desktop shell on Linux

The Tauri shell in `src-tauri/` builds and runs on Linux (checked on Ubuntu 24.04 with WebKitGTK 2.52.6). Install the packages first:

```bash
sudo apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev libsoup-3.0-dev libjavascriptcoregtk-4.1-dev
```

Add `xvfb` for a headless check. Build with `cd src-tauri` and `cargo build --release` (about 6 minutes); the binary is `src-tauri/target/release/formweb`. The shell reuses a FormWeb service of its own version already running on port 8240; if another program or another FormWeb version holds 8240, it starts its own service on the next free port up to 8279. Run it with `FORMWEB_ROOT` set to the repository. Under Xvfb also set `WEBKIT_DISABLE_DMABUF_RENDERER=1`. Closing the window shuts the shell down and leaves no process behind.

At 1440 x 900 the top bar, Team libraries, the Library panel, Preferences, Remove background, the brand kit, the stock dialogs and the Projects dialog match Chrome. Since 0.20.5 every select draws its own chevron, so selects look the same and show their whole value in both engines (the Desktop select reads in full in every language). Since 0.20.6 sliders, checkboxes and number fields share one look too: a grey track with an accent knob, a grey rounded box with an accent fill and a dark check, and spin buttons that appear only when you point at or focus the field.

The command palette (Ctrl+K, or the search button in the title tools) finds a command by its name and menu in the interface language as well as in English, or by its id, ignoring case and accents, so "marken" finds "Fenster > Marken-Kit..." in German and "offnen" finds "Projekt öffnen...". Outside English, names that start with what you typed come first. The rows show the names in the interface language and follow a language change at once. A language change in Preferences re-translates every label from its English source, and Japanese, Chinese, Korean and Thai text uses fallback fonts with Inter's line height, so switching moves little: the inspector keeps the same tabs and columns as in English where they fit, and only labels whose width changes, such as menu names and buttons, shift sideways.

## Advanced studio

Open **Studio** in the menu for advanced authoring and service workflows. Choose a category, review its example using the current element/locale, then run the operation. The result panel shows the actual engine revision or service response. JSON editors are parsed locally and validated by Rust or the service. Pending Studio input remains mounted during live updates.

**Load current configuration** reads a persisted extension group before editing it; saving that group replaces it. Dedicated state, timeline, overlay, media, route, widget and experiment workflows merge their own entry into current configuration. Use IDs from the inspector or returned service lists. [The advanced guide](ADVANCED_GUIDE.md) provides exact schemas and worked examples.

## Pages and elements

Use the Pages list to select a route or add a page. Page settings edit its name, slug, title, description and indexing preference. The Layers list describes its node hierarchy. Select a layer or click an element on the canvas to edit it. Double-click text on the canvas to edit its content.

Right-click a page in the Pages list (or focus it and press the Menu key or Shift+F10) for Open, Rename, Duplicate, Set as home page, Move up, Move down, Page settings and Delete. Duplicate copies the page with everything on it under a free name and address, such as "Hello copy" at /hello-copy, then /hello-copy-2, and opens the copy. Set as home page moves the page to the top of the list, where the editor marks it Home, and gives it the / address, so the export's index.html is that page; the old home page gets an address from its name (for example /home), links and click actions that pointed at the page's old address now point at /, and links to / now open the new home page. It is off for the page that is already home. It refuses, and says why, when either page is a CMS template page (it makes one page per item, not a page at its own address) or has its own address in another language (CMS > Localization), and for a page a password protects through a route other than / (at / it would be open to everyone); a password on / protects every page either way. Delete opens the usual confirmation and a site always keeps one page. The layers context menu has Copy, Cut, Paste and Duplicate, then Rename and Delete, then Move up and Move down. Inside a menu the arrow keys, Home and End move between items, Enter runs one and Escape closes it. Every item is also a command in the Page or Edit menu and in command search (`page.open`, `page.rename`, `page.duplicate`, `page.set-home`, `page.move-up`, `page.move-down`, `layer.rename`), and each change is one undo step.

Right-click an element on the canvas for its menu at the pointer (with the canvas focused, the Menu key or Shift+F10 opens it at the selected element). The element is selected first unless it is already selected. Right-clicking an element that is part of a selection of several keeps the whole selection and makes that element the primary one; the labels then say how many elements each action changes ("Duplicate 3 elements"), and Copy, Cut, Duplicate, Delete, Move up, Move down and Paste styles act on the whole selection as one undo step, while Wrap in container wraps the selected elements that sit beside the clicked one in the same parent and the status line says how many others were left as they are. The menu has Edit text (for an element with its own text; the same as a double click), Copy, Cut, Paste, Duplicate and Delete, then Rename and Select parent, then Move up, Move down, Wrap in container and Add element here..., then shortcuts into the right panel for the fields that apply to the element: Text style, Background, Spacing, Size, Link (links) and Image source and alt text (images), each opening the right panel on the right tab with that field focused. Last come Copy styles and Paste styles. Wrap in container puts the element inside a new empty div at its place and selects the div. Add element here... opens the Quick insert flyout, which inserts into the element when it is a container and after the last child of its parent otherwise. Copy styles remembers the element's styles for the breakpoint picked in the toolbar (the base styles on Desktop, the overrides on Tablet or Mobile), in this window only; Paste styles gives every selected element exactly those styles for the picked breakpoint, removing styles the copy lacks. Right-click the page itself, where no element is under the pointer, for Paste, Add element here..., Page settings and Page background. For an element inside a linked component instance the items the instance does not allow (copy, cut, duplicate, delete, move, wrap, paste or add inside it) are greyed out and their tooltip says why; the same applies to Move up on the first element and Move down on the last. While you are editing text on the canvas, right-click shows the browser's own menu, so spelling suggestions and the clipboard stay available. Every item is also a command in command search, Edit text, Select parent, Copy styles and Paste styles are in the Edit menu and Wrap in container in the Arrange menu (`edit.text`, `edit.select-parent`, `edit.wrap`, `style.copy`, `style.paste`, `inspector.text-style`, `inspector.background`, `inspector.spacing`, `inspector.size`, `inspector.link`, `inspector.image`), and each change is one undo step.
To rename a page or a layer, double-click its row or focus it and press F2: the name becomes a field of the same size in place. Enter or clicking elsewhere keeps the new name, Escape keeps the old one, and an empty name is refused with a note in the status line. A single click still selects at once. This renames the page or layer only; a page's address stays in Page settings. Rename from a menu or command search works the same way, and when the list is hidden it opens the Name field in the inspector instead.

The PAGES and LAYERS headings fold their lists: click the heading to hide or show it. A layer with children has a small arrow before its icon; click it to fold or unfold that layer's children. With a layer row focused, Right unfolds it (or moves to its first child), Left folds it (or moves to its parent), and Up and Down move between rows. Collapse all and Expand all are at the bottom of the layers context menu and in command search (`layer.collapse-all`, `layer.expand-all`); Collapse all leaves the page and its top-level elements in view. Selecting an element on the canvas or in the selection path unfolds the layers above it. Folding is remembered per page on this computer only (it is not saved in the site or the .fweb file), and so is which headings are folded; Settings > Reset All Preferences forgets both.

Drag a layer to move it. An orange line shows where it will land: drop on the upper third of a row to put it before that row, on the lower third to put it after, and on the middle of a container (section, div, header, footer, nav, form, list and the like) to put it inside, last; the container is outlined. Dropping on the lower part of an unfolded container puts the layer first inside it. A layer cannot go inside itself or one of its own layers, the page itself cannot be dragged, and the structure of a linked component instance cannot change (detach it first); where a drop is not allowed no line shows. Drag pages the same way to reorder them; the page that ends up first is the home page the editor opens and marks Home (use Set as home page to also give it the / address). The list scrolls when you drag near its top or bottom, Escape cancels a drag, and each drop is one undo step. With a row focused, Alt+Up and Alt+Down move the layer among its siblings, or the page in the list, as Move up and Move down do. Agents and scripts reorder pages with the engine command `page.move {id, index}`.

You can also move elements on the canvas itself. Click an element to select it, then press on it and drag; the drag starts once the pointer has moved a few pixels, so a click still only selects and a double-click still edits text. A label with the element's name follows the pointer, the element stays dimmed in place, and an orange line shows exactly where it will land: between two siblings, along the direction they flow in (a horizontal line for elements stacked in a column, a vertical one for elements side by side in a row or a grid). Over the empty part of an empty container the container fills with orange instead, and the element goes inside it. Elements only ever land in a place in the layout, never at a free position, so nothing is given offsets and nothing flies around; the dashed outline shows the container the element will end up in. The canvas uses the same rules as the Layers list: the page itself cannot be moved, an element cannot go inside itself, only containers take children, and the inside of a linked component instance cannot change (pointing at it places the element before or after the whole instance). Release to drop: the move is one undo step, the element stays selected and the Layers list shows its new place. With several elements selected, dragging one of them moves them all, in one undo step: the label reads how many ("3 elements"), and they stay selected after the drop. Ctrl, Cmd or Shift with a press only changes the selection and never starts a drag, and a plain click on one of several selected elements selects just that one when you release without dragging. Releasing outside the canvas, or where no line shows, leaves everything as it was, and Escape cancels the drag. Drag near the top or bottom edge of the canvas to scroll the page. Dragging works at every canvas zoom and scroll position, and never starts while you are editing text.

Select several layers to act on them together. A click selects one layer; Ctrl+click (Cmd+click on a Mac) adds a layer to the selection or takes it out; Shift+click selects every visible row from the last layer you clicked to this one. With a layer row focused, Shift+Up and Shift+Down extend the selection one row at a time, Ctrl+A (Cmd+A) selects the selected layer and its siblings and a second press selects every layer on the page, and Escape goes back to one layer. On the canvas, Ctrl+click, Cmd+click or Shift+click an element to add it or take it out. The last layer you picked is the primary one: its row is highlighted as before and it has the solid outline on the canvas, while the others get a lighter highlight and a dashed outline. The inspector then reads "3 elements selected" and the line under it names the primary element, because the controls still edit that one only. Copy, Cut, Paste, Duplicate, Delete, Move layer up and Move layer down (the Edit and Arrange menus, their keys and the layers context menu, whose labels then read "Duplicate 3 elements") act on the whole selection as one undo step. Delete element has two keys, Delete and Backspace (the delete key of a Mac laptop); neither deletes an element while you type in a field or edit text on the canvas. When you select an element together with something inside it, they act on the outer one only; the page itself and elements inside a linked component instance are left out of Copy, Cut and Duplicate (and of Delete, the page and the elements directly inside a linked instance), and the status line says how many were skipped. Duplicate selects the copies, each right after its original. Paste after a copy of several elements pastes all of them, in order, after the selected element. Copy and Cut take at most 64 elements at a time; for more, select their container. Move up and Move down move the selected layers as a block within each parent, and nothing moves when the block is already at the edge. Dragging a selected layer drags the whole selection (dragging a layer that is not selected drags only that one), and Alt+Up and Alt+Down on a selected row move the whole selection. Right-clicking a selected layer keeps the selection; right-clicking another layer selects only that one.

The Pages list follows the same rules: click opens one page, Ctrl+click or Cmd+click adds or removes a page and Shift+click selects a range (the page you clicked last is open on the canvas), Shift+Up and Shift+Down extend, Ctrl+A selects every page and Escape goes back to the open page. Duplicate, Move up, Move down and Delete in the page context menu then act on all the selected pages ("Delete 3 pages..."), as do Page > Duplicate page, Move page up, Move page down and Delete page...; a page command given a page that is not part of the selection acts on that page alone. Delete asks once, naming the count, and refuses to remove every page: a site keeps at least one. Dragging a selected page moves the selected pages as one block. Each of these is one undo step. The selection is kept in the editor only and is never saved with the site.

On a touch screen or with a pen, dragging rows and elements works too. A pen works exactly like a mouse: press and move, and the drag starts after a few pixels; a press with the pen's barrel button held never starts a drag. With a finger, a drag starts with a long press: hold a page row, a layer row or an element on the canvas still for about a third of a second until it lifts (the row is highlighted, the element gets a wider outline, and the device gives a short buzz where it can), then move without lifting. An ordinary swipe still scrolls the list or the canvas, and a tap still selects. A long press on an element that is not selected selects it first. While you drag, the list or the canvas holds still under your finger and scrolls by itself near its top and bottom edges, and the same orange line shows where the drop lands. Lifting your finger outside the list or the canvas, or where no line shows, moves nothing; a second finger on the screen, or the system taking the touch over, cancels the drag and nothing moves. A long press that you release without moving opens the right-click menu of that row or element, which is how you reach it by touch. To select several without Ctrl or Shift, turn on Select several: the button with two ticked boxes in the Pages and Layers headings, or Edit > Select several (command `edit.select-mode`). While it is on, a tap or click on a layer, a page or an element on the canvas adds it to the selection or takes it out, as Ctrl+click does; the headings show how many are selected ("3 selected") and a Done button in place of their titles, and a double tap does not rename or edit text. Done, Escape or the button again turns it off and keeps the selection. It works with a mouse and the keyboard as well.

A page's background is the background of its root element. A new page has none, so it is white with black text, the browser default, both on the canvas and in the export; the home page of the sample site sets `var(--paper)`. To change it, open the Page tab of the inspector (or Page > Page background...) and type a color, a `var(--token)` or a gradient in Page background > Background; the color list offers your brand colors, and the brand restriction applies here as in Appearance. A value the browser does not read as a CSS background is refused with a status message and the field returns to the page's current value; Apply to all pages refuses such a value in the same way. The line under the field says what the page uses: its own value (with the token's value), or the site background, plus which other page sets a background you may want to match and which breakpoints override it. The field always writes the page root's base (desktop) style, whatever breakpoint the canvas shows. Clear (also Page > Clear page background) removes the page's own background, and the `background-color` too if one was set elsewhere. Apply to all pages (Page > Use this page background on all pages) gives every page this page's background, or clears them all when this page has none, in one undo step. Edit site theme colors opens Window > Design system at its Themes block, where token values such as `--paper` get their light and dark values. A site with no themes says so there: Default theme reads None, and the moon and sun buttons above the canvas are greyed out and unpressed, because the export has only one set of colors; picking Dark or Light starts the themes and None removes them. The same value can be set from the Design tab's Appearance > Background with the page root selected.

Insert adds primitives such as a section, text, grid, image or form into the selected structure. Image insert opens a file picker for PNG, JPEG, WebP or GIF up to 8 MiB; Content > Upload image replaces the selected image. A new image has no alt attribute until you describe it, so the audit lists it ("Image needs alt text (empty alt is valid for decoration)"). Type the description in Content > Alternative text; clearing the field removes the attribute again. For a picture that carries no meaning, tick Decorative image (no description) under the field: it writes an empty `alt=""` on purpose, which screen readers skip and the audit accepts, and turns the text field off until you untick it. Sites made before this keep their images exactly as they were. Uploaded raster files are validated, stored locally and bundled into website export. Layers supports ordering and moving elements under a parent. Edit > Duplicate element (`Mod+D`) and the Duplicate item in the layers context menu copy the selected element with everything attached to it (motion, code sections, variables) and select the copy, which lands right after the original; one undo removes it. Both are disabled for a page root (use the page's own duplicate) and inside a linked component instance, and the item's title says why. `Shift+Mod+D` always duplicates, including while a vector transform is repeatable and `Mod+D` runs Transform again. Edit > Copy element (`Mod+C`), Cut element (`Mod+X`) and Paste element (`Mod+V`), also in the layers context menu, move an element through the system clipboard as fragment JSON that carries its motion, code, variables, page components and picture references. Paste inserts after the selected element under its parent, or last in the page root, with fresh ids, and selects the pasted element; it works on the same page, another page and another site on this FormWeb. Copy and Cut also embed the pictures (up to 16 MiB), so the copy pastes in another FormWeb installation too; the status says how many pictures were too large to embed, and a refused paste shows the reason in the status. Cut is a copy followed by a remove, and each paste or cut is one undo step. While text is selected outside the canvas, `Mod+C` and `Mod+X` stay with the browser so you can copy that text, and `Mod+V` uses the browser's paste event, so it needs no clipboard permission; the menu items read the clipboard and tell you how to allow it if the browser refuses. Clipboard text that is not a fragment does nothing. A paste keeps the site's own code component or variable when its name already exists with a different definition, and says so; the fragment also carries the design tokens, text presets and themes the element uses and the CMS collections it is bound to and any collections those refer to, the variables its set-variable actions name, and its form configuration (past 500 items a collection travels as its first 500 plus every item a binding, list filter or reference names, with a warning counting the rest), and a paste adds what the site lacks and keeps the site's own on a name clash with a different value, with a warning for each clash; code sections need the site to allow them; pasted pictures must exist on this FormWeb; and a page root, an element inside a linked component instance and more than 2,000 elements cannot be copied. Copy and Cut keep large pictures and videos behind a 15-minute clip link on this FormWeb, so the element also pastes in another FormWeb on the same computer while this one is running; the status says how many assets will only paste on this computer. Images are limited to 8 MiB and videos to 64 MiB. A paste streams each clip asset to disk and checks it as it arrives, so a very large video does not fill memory, and nothing is stored if the paste is refused. A copy of a copy keeps a short element id (the earlier -copy-N or -page-N ending is replaced rather than extended), and labels, aria-labelledby, #links and button actions inside the copy point at the copy's own elements; ids you wrote yourself, such as step-copy, are never shortened. Since 0.20.3 a copy also carries the ids of the element's ancestors at the source, so a child you copied out of an earlier copy and paste into another site swaps its ending at once (label-copy-1 becomes label-copy-2, not label-copy-1-copy-2). A copied element keeps its behavior actions. The inspector's Design and Content surfaces change styles, attributes and text; the Page surface changes route metadata.

The plus button in the Layers header opens Quick insert, a small flyout under the button (above it when there is no room below) that lists the Insert panel's Elements, Sections and Components. Type in the filter to narrow the list, move with Up and Down (the highlight wraps), and press Enter or click to insert; Escape, a click elsewhere or Tab closes it and Escape or Tab returns focus to the plus button. The choice is inserted exactly as the Insert panel would insert it: elements into the selected container, a section after the selected top-level section, a component instance into the selected container, each as one undo step. The last row, All elements and components..., opens the full Insert panel, which also holds Starter pages and Capture selection. Insert > Quick insert (`Mod+Shift+L`, command `insert.quick`) opens the same flyout, showing the left panel first when it is collapsed. The plus button next to Pages still opens the Add page dialog. There the URL slug follows the page name as you type (lower case, ASCII, words joined by hyphens, so "Café Menu" becomes `/cafe-menu`) until you edit the slug yourself, and a line under the fields shows the address that will be used, with the site's base URL once it is set. An address another page already uses, or one with characters an address cannot hold, is named on that line in red and the dialog stays open; nothing is renamed behind your back. With both fields empty the page is called Untitled page at `/untitled-page`.

A website layout uses normal browser flow, flex and grid styles. Use meaningful element names and a clear hierarchy. A stored value becomes part of the site only after the engine acknowledges it. Invalid changes are reported; they do not replace the previous document.

### Search properties

The right panel has a search field between its tabs and its fields. Click it, or press `Ctrl+Alt+F` (`Cmd+Option+F` on macOS; Window > Search properties, command `inspector.search`), which also opens the right panel when it is collapsed. Type a word and the panel shows one list of matches from every tab at once (Design, Motion, Content and Page), grouped as tab > section, for example Design > Appearance with Background, Radius and Shadow under it.

A field matches on its label, its section title, its CSS property name (`padding`, `border-radius`, `font-size`) or a related word: `bg`, `colour` and `fill` find Background and Color; `rounded` and `corner` find Radius; `elevation` finds Shadow; `spacing` finds Padding, Margin and Gap; `font` and `text` find Typography; `href` and `url` find Link URL; `alt` finds Alternative text; `seo` finds the page title and description. Several words must all match. Case does not matter.

Press Up and Down to move through the list and Enter, or click, to go there: the panel switches to that tab, opens the section if it was collapsed, scrolls the field into view, puts the cursor in it and outlines it for a moment (a steady outline when your system asks for reduced motion). Escape clears the search and shows the panel exactly as you left it, with the same tab and scroll position; the clear button in the field does the same. Fields the panel hides for the current selection, such as the image buttons while a heading is selected, are not listed. Fields that are shown but switched off, such as Clear breakpoint overrides on the desktop base, are listed as Unavailable. The list follows the selection while it is open.

## Responsive design

Desktop, Tablet and Mobile select the responsive profile and set the frame to that profile's width. Default tablet and mobile maximum widths are 991 px and 767 px. Studio > Layout & design creates custom breakpoints; the toolbar dropdown selects any stored profile, and the stage header names the profile being edited. Typing a width only resizes the frame: the canvas keeps drawing and editing the picked profile's styles, and a quiet hint appears when the width falls outside that profile's range. The hint has a place of its own in the stage header, on up to two lines, so it never moves anything when it appears or goes, and a long selection path shortens beside it instead. On a page with a scroll scene the scene scrubber shares the header: below about 1,100 px of header it keeps only its scene list, slider and Off, and on a very narrow canvas (about 560 px) the hint gives its place to the scrubber; the readout still shows the width. To watch the design switch as the width changes, turn on View > Live responsive preview: it shows the exported site at the typed width, so the browser's own media queries do the switching. Design includes flex wrapping/order, grid rows/placement/spans and self alignment. Inspect each profile after changing layout or type.

Preview compiles the selected page and locale through the backend and loads the actual exported runtime in an isolated iframe. The preceding design/runtime stays visible until the new preview loads. The refresh icon beside the Preview button recompiles it and turns it on, and stays pressed while it is on; Back to design in the preview's frame label, or View > Live responsive preview again, returns to design. The design canvas remains a script-free selection surface, while advanced CMS queries, templates and widgets are reviewed in compiled Preview. Narrow-screen layout still requires author judgment.

Preview as published (the Preview button with the eye, View > Preview as published, Ctrl/Cmd+Shift+P) opens the compiled site over the whole window, with none of the editor around it. The bar along the top has:

- a page picker; when you follow a link inside the preview it reads "Page opened from a link" until you pick a page again;
- widths: Full width (the whole window) and one button per breakpoint of the site, named with the breakpoint and its width (the width you last typed for that breakpoint, kept inside its range). A width sizes the preview only; the exported CSS switches layouts by the browser's own media queries, as on the published site. Narrow widths are scaled down to fit the window;
- for phone and tablet widths, Rotate (swaps width and height) and Device frame (a plain drawn frame, on by default);
- a language picker when the site has more than one locale;
- the revision on show, Refresh (compiles the current revision again), and Open in browser, which opens the same compiled page in your browser (in the desktop app, your system browser). That link is private to this computer and works for one hour;
- Close. Escape and Ctrl/Cmd+Shift+P also close it, and the Preview button gets the focus back.

While it is open the editor underneath cannot be clicked or reached with Tab, its menus and shortcuts do nothing, and when the site changes (for example an agent edits it) the preview compiles the new revision and swaps it in once it has loaded. If you followed a link inside the preview it stays where you are and says the site has changed; press Refresh. Keys typed inside the previewed page belong to that page, so click the bar before pressing Escape.

## Components and tokens

Capture a subtree as a source component, then insert a linked instance through the Components list. Studio > Components & libraries defines typed properties, variants and slots using source element IDs. Instance operations address the instance root: set properties, apply a variant, fill slots with existing elements, reset inherited fields or detach while keeping its materialized content.

Save an immutable component library with a stable ID and semantic version. Initial import needs a parent element. For an existing pin, review the target version, inspect added/removed/changed sources, then explicitly acknowledge its returned digest when updating. Detach retains local copies. Studio > Layout & design defines typed CSS tokens and reusable text presets; apply a preset to an element and inspect its resulting styles.

Build isolated code component requires an explicit source-enable checkbox. It compiles a self-contained module exporting mount(root, props) with typed property descriptors. Diagnostics block installation. Successful source/build digests and the installed revision appear in the result. Component code runs in an opaque iframe with parent access and external network blocked.

A component can have a light poster as well as a poster. In the components inspector, Light theme poster holds its path, Upload light poster sets it and Clear light poster removes it. When the site has themes, the export shows the dark poster in the dark theme and the light poster in the light theme until the component draws its first frame, and the canvas shows the light poster while the Design system dialog previews the light theme. A component without a light poster shows its one poster in both themes. When a component is placed on more than one element, or an element already has a poster of its own, the poster fields in the inspector change only the selected element (its own poster and light poster, kept with its instance); the other elements keep the component's.

## CMS and translations

Create a collection and add typed items through CMS. Studio > CMS & content edits existing schemas, including reference/reference-array fields targeting other collections. Selected text, image source or link bindings can use related fields such as author.title. List queries filter, sort, limit and paginate published items, with an optional authored empty-state node. Templates compile detail pages using item slugs and metadata. Draft and archived records remain editable and are excluded from output.

Export collection CSV, edit its typed values, then upload it through Import collection CSV. Upsert retains other records; replace removes records absent from the file. Presence/null/locale metadata preserves missing, empty, null and translated values. Invalid rows reject the entire import; the result reports created, updated and removed counts.

Locales stores node text and page metadata dictionaries. Studio > Localization & SEO adds translated page routes/media, all-locale output, the base URL (Base URL and SEO settings), metadata templates, JSON-LD and robots rules. CMS items can have translated values, slug and status. Connected providers can propose translations for explicit review at an expected revision. Missing translations still need editorial review.

## Library

The Library tab in the left rail holds finished sections, design presets and starter sites. It has three views: Sections, Kits and Import HTML.

Sections shows category chips (Product site, Scroll story, Portfolio hero, Prompt hero, Support, Not found, Chrome; the 7 bundled categories paint at first paint, so the row's height follows the sidebar width and does not change when the index loads, though a category the bundled list does not know adds a chip when the index arrives), a search field that matches name, tags, product and description, and a grid of cards with a thumbnail, the name and a badge when the section uses a page component. Select a card to open its detail in place: a larger thumbnail, a description, the fields you can re-cast before inserting (a colour field with a swatch for the tint, text, links, pictures) and Insert section. Insert places the section after the selected top-level section, or at the end of the page, as one undo step, and selects its root. Inserting the same section twice gives two independent copies. A note under the button warns when a section shares variables with one already on the site.

An inserted section is built from your site's tokens and text presets, so changing a token restyles it. Inserting also adds only what the site is missing from the section's preset (tokens, light values, the font, text presets, root styles) and never overwrites your own values.

Kits lists presets and starters. Apply preset sets every value the preset defines, including ones you changed, and is one undo step. Use starter asks for a product name and a tint, then adds the starter's pages and sections in one step; the first page replaces an empty home page.

Import HTML turns a pasted page, or an `.html` file you pick, plus optional CSS into one code section on the page. File > Import HTML... (also in the command search) opens the Library straight on this tab. Code sections must be allowed for the site, which Import HTML turns on. The view explains this in plain words; its tooltip keeps the technical note: the page's styles and first module script come along, the formai kit helpers `reduced`, `onTheme` and `token` are provided to that script, and a code section runs its own JavaScript in Preview and in exports. Relative pictures and scripts in the pasted page are not brought along, nor are script elements that are not JavaScript, such as JSON-LD structured data (a note says so; add structured data again in Studio > Localization & SEO), and the section does not run on the canvas, so open Preview to see it. [The library guide](LIBRARY.md) describes the template format, components, routes and limits.

Import site from zip (File > Import site from zip..., or Import site from zip... at the top of the Import HTML view) brings in a static site built elsewhere. Pick a `.zip` that holds its HTML, CSS, JavaScript, pictures and fonts. Nothing changes until you confirm: the review lists each page with its file and the address it will get (`index.html` becomes `/`, `blog/index.html` becomes `/blog`, `about.html` becomes `/about`; an address the site already uses gets a new one such as `/home`), the number and size of the pictures and fonts, and every file that is skipped with the reason. Add as new pages is the default. Replace matching routes is offered only when an imported address matches a page you already have and nothing else on the site (a component, code, motion or variables entry) points into that page; it keeps the page and its address and swaps its content, so a site you imported before can be imported again over itself. Import does everything as one undo step and reports, for example, "Imported 5 pages and 23 assets. 2 files were skipped.", with the skipped list still shown.

Each imported page holds one code section, the same thing Import HTML makes: the page's body as HTML, its `<style>` blocks and local stylesheets as CSS (with `@import` and `url()` followed; stylesheets that import each other in a loop arrive once each, and the review names the loop; imports are followed 4 levels deep, and the review names any stylesheet left out past that; a page whose styles pass 256 KiB is skipped with the stylesheet that crossed the limit named), and its first script, local or inline, as JavaScript, under Import HTML's script rules. Edit them as code; they run in Preview and in exports, not on the canvas. Pictures (PNG, JPEG, GIF, WebP, SVG), MP4 and WebM videos and WOFF2 fonts go to your assets and every reference to them is rewritten; links between the imported pages point at their new addresses; outside links stay as they are. The page title and meta description fill the page's SEO fields. Left out, with a note: the page head, external stylesheets and scripts in it, scripts after the first, script elements that are not JavaScript (such as JSON-LD, the same as Import HTML), other font formats, icons in ICO format and any other file type. The archive is checked before it is opened: at most 64 MiB, 1,000 entries, 100 pages, 12 folder levels and 128 MiB unpacked, each file within the asset upload limit for its type; a zip with a file outside its own folder, a link, a password or a file that expands suspiciously is refused whole. System files (`__MACOSX`, dotfiles, `node_modules`) are ignored, and a single top folder is stripped.

## Save, reopen and import

Save writes the active editable project to the local project library. While an isolated branch is open, Save captures that branch. Projects lists main snapshots and opens one back into the engine. Download creates an editable `.fweb` envelope containing the model, checkpoint/history and uploaded raster assets. Import validates and restores the full envelope; a bare site JSON remains accepted. A project that fits in 64 MiB downloads as a single JSON `.fweb`. A larger one, such as a project with several videos, downloads as a version 2 `.fweb`, a zip with `project.json` and the assets stored uncompressed; Import reads both kinds, up to 512 MiB, and rejects a damaged or inconsistent zip before storing anything. A large load reads each file once and runs without blocking the server, so a 74 MiB project with two videos opens in a fraction of a second. Individual images are limited to 8 MiB. New creates a starter document with a distinct identity.

File > Import .fweb or .fpub file... (and the project importer) also opens a `.fpub`. A `.fpub` is the single-file package FormPublisher saves for a build: a zip that holds exactly `fpub.json`, `publish.json`, `site.zip` and, when signed, `site.zip.sig`, in that order. FormWeb checks the format (`formpublisher-package`, version 1), the package record, and that `site.zip` matches the size and sha256 recorded in both `fpub.json` and `publish.json`. It then loads the site from `site.formweb.json` inside `site.zip`, with the images and other assets the site uses, which keep the same sha256 ids. Nothing is stored until every check passes; a refused file leaves the open document unchanged and its staged files are removed. FormWeb does not check the signature (`site.zip.sig`): FormPublisher does when it opens the same file, so open a signed package there to verify it. A `.fpub` built from a site FormWeb did not make has no `site.formweb.json`, and FormWeb refuses it with a message pointing to FormPublisher.

Undo and redo operate on engine changes. An agent command batch is one atomic undo step. Save before starting a separate project if the current work must be retained.

## Audit and export

Run Audit to inspect model issues. Select on an issue opens its page, selects the element, scrolls the canvas so the element is in the middle of the view and its outline pulses for about two seconds (with reduced motion it stays still and wider for the same time); the layer row scrolls into view and the status line names the issue, for example "Selected Hero image: Image needs alt text (empty alt is valid for decoration)". An issue about the whole page (a missing title or description) or the base URL opens the Page inspector instead and flashes that field. Picking a layer in the left panel, or a step of the selection path above the canvas, also scrolls the canvas when that element is out of view; a click on the canvas itself never scrolls it. Then check hierarchy, links, media alternatives, forms, headings and narrow widths visually. The audit is an aid and does not certify all accessibility requirements. A form that posts (one with no submit script and no action of its own) gets the warning `forms.local-address`: Export static site writes its action as this computer's FormWeb address, so on another host the form sends nothing. The warning names the page and selects the form. Give the form a scripted reply (Motion > Script with the Submit trigger) or keep the site on this computer with Publish; an export's warnings list carries the same sentence, and the status line shows it after an export or a send (a site without such a form shows nothing). A local publication and Preview are served by FormWeb itself and are not flagged.

Export downloads static HTML/CSS/JavaScript, uploaded assets, route metadata and configured runtime behavior. All-locale output includes translated routes and alternate-language metadata. Review warnings and open the exported pages. Keep editable source as well as the ZIP. When the site has a form that posts to this computer, the status line after File > Export static site adds that page's `forms.local-address` sentence, after any 404 base URL warning. The line starts with the language that was exported, named in the interface language ("Static site exported for English."). While the ZIP is being made the toolbar's Export button shows a progress pointer and its icon pulses (it stays still with reduced motion), and neither the button nor File > Export static site starts a second export. When it is done a notice at the bottom right names the file and where it went, and stays about 12 seconds (longer while the pointer is on it): in a browser "Downloaded coldmere-site.zip", and the browser's own downloads list shows the file; in the desktop app, which saves straight to your Downloads folder without a prompt, "Exported coldmere-site.zip to" the folder it was saved in, with a Show in folder button that selects the file in Finder or File Explorer (on Linux it opens the folder). The desktop app names the file it really wrote, such as `coldmere-site (1).zip` when an older export is already there. If the export fails, or the desktop app could not write the file, the notice says so in red as well as the status line. File > Download .fweb project shows the same notice. Gated member content requires the authorizing backend; public static export is rejected rather than exposing it.

File > Send to FormPublisher (also in the command palette) exports the open site and hands it to FormPublisher on the same computer (a refusal names its code in brackets, for example `[not-a-site]`), the app that checks, builds and publishes a finished site. When FormPublisher is running the site arrives live and the status line shows the site and its revision, followed by any export warnings; if the 404 page has no real base URL, the warning carries a Set the base URL action that opens the Base URL field in the page inspector's Whole site section (a warning raised while a dialog is open shows the same action in the dialog's footer, and clicking it closes the dialog first); sending the same site again files a new revision of it, not a second site. The hand-off is a plain export, so a form that posts to this computer adds the same `forms.local-address` sentence to the status line, whether the site arrives live or goes to the inbox. When FormPublisher is not running, the ZIP is written to its inbox folder instead (`inbox` inside `FORMPUBLISHER_HOME`, by default `~/FormPublisher/inbox`) and the status line gives the path; FormPublisher imports it the next time it starts. FormWeb finds FormPublisher in this order: `FORMWEB_FORMPUBLISHER_URL` if you set it; then the `engine.json` that FormPublisher writes in its data folder (`FORMPUBLISHER_HOME`, by default `~/FormPublisher`), whose port is used only if `/api/health` on this computer answers as FormPublisher; then `http://127.0.0.1:8280`. A FormPublisher on another port is therefore found without any setting. Sending does not change your site or leave the editable project: keep saving the `.fweb` file.

Publish creates an immutable local version served by the running API. Studio > Publishing & delivery lists releases and promotes or rolls back the active /sites/ route; previous version URLs remain separate. Portable redirects map old routes to destinations, with cycles rejected. A rule may end in one star, such as `/old/*` to `/new/:splat`, to move a whole section. A page routed at `/404` is also exported as a root `404.html`, and a published release answers a missing path with that page and status 404 (an unpublished preview does too). Set the base URL to the site's public address before deploying under a path: with it unset or example.com, export warns and the audit reports seo.base-url-404. Emptying the Base URL field removes the setting, and the site is treated as on the https://example.com placeholder (the field's help ends with "Leave it empty to keep the https://example.com placeholder."). Provider deployment/domain workflows are separate configured adapter calls: inspect their returned status and verification requirements before treating them as usable public output.

Local forms write to the persisted inbox. Studio reads/export CSV, applies retention, configures signed delivery destinations by server secret-environment name and inspects/retries the outbox. Retention deletes persisted submissions outside site undo. A site on another host needs an available backend/form endpoint; credentials remain on the server.

## Review, members and providers

Studio > Review & access creates and opens an isolated branch. Edit, then Save/capture branch work. Read Saved main projects and Return to main project before review or merge. Review reports changed JSON pointers and conflicts; merge chooses current/branch for every conflict at the reviewed revision. Comments, resolution, presence and activity are persisted and attributed. Saved-project deletion is outside site undo.

Editor identities require a configured FORMWEB_AUTH_TOKEN. Create an identity, securely retain its once-returned token and grant viewer/reviewer/editor/publisher/owner access. Visitor membership is a separate runtime service: member-login/member-gate widgets and the visitor registry use their own groups and sessions.

Connected providers reports available adapters and missing server environment names without exposing secrets. Deployment, domain, translation, data fetch and commerce workflows show actual transport/status results. Translation proposals require explicit review. Runtime widgets consume configured sources, products/cart/hosted checkout, membership and analytics consent. Weighted experiments wait for consent, and an explicit authored conversion goal is distinct from assignment. Independent provider/domain/payment verification is still required before production claims.

## Author with an agent

Start the editor/service and enable Agents. FormWeb works with four agent programs: Claude Code, Codex, Cursor and Antigravity (Google's `agy` program). The repository includes project MCP configurations for Claude, Codex and Cursor. Antigravity reads one file for the whole account, `~/.gemini/config/mcp_config.json`; the Antigravity card in Agent Connect adds FormWeb's entry there when you ask. Use `./formweb agents install` to see paths and commands without changing global configuration. On Windows configure an absolute `formweb.bat` path with the `mcp` argument.

The `formweb-harness` skill guides an agent through reading, planning, atomic commands, responsive inspection, audit, save and export. MCP exposes the same active document as the editor. An agent should obtain live ids and command schemas before changes and refresh state after a revision conflict.

Agent access defaults off. `FORMWEB_AGENTS=1` is available for a deliberately configured local session; once the engine is running, only the FormWeb window can switch it or change the approval choices, and an outside agent asks the person to. `FORMWEB_AUTH_TOKEN` can restrict control requests further. `./formweb mcp` requires the running HTTP service and does not start an isolated engine.

## Troubleshooting

- macOS says the app cannot be opened, or that Apple cannot check it. A build signed with a Developer ID but not notarized is stopped by macOS on its first open after a download. Right-click (or Control-click) FormWeb in Applications and choose Open, then Open again in the dialog. On recent macOS versions open it once, dismiss the message, then go to System Settings > Privacy and Security, find the line about FormWeb and click Open Anyway. macOS asks only this once.
- A message that begins "FormWeb could not start" appears instead of the window. The app's local service did not start: the message says why (it stopped, with its code, or it did not answer within 90 seconds), shows the last lines the service wrote, and names its log file, `logs/formweb-engine.log` in the data folder. "Another copy of its engine holds its data folder" means a FormWeb engine from an earlier start still runs on the same data. From a source checkout, run `./formweb doctor`. The app uses port 8240 only when that port is free or a FormWeb service of the same version already answers there; when another program holds 8240 it starts its own service on the first free port from 8241 to 8279, and it stops with a message only when none of them is free. Set `FORMWEB_PORT` (8240 to 8279) to make another port the first choice.
- Double-clicking a `.fweb` project or a `.fpub` package opens it in the desktop app. If the open site has changes that are not saved as a project, Home asks before it is replaced. On Windows and Linux, opening a file while FormWeb already runs hands it to the running window instead of starting a second copy; on Linux this needs a D-Bus session bus, and without one a second copy still starts.
- Export static site or Download project seems to do nothing in the desktop app: the file is saved to your Downloads folder on macOS, Windows and Linux alike, and the notice at the bottom right names it; Show in folder opens it there.
- A form on an exported site sends nothing. Run Audit: the warning `forms.local-address` names the form (see Audit and export).
- A page component shows only its still picture on a published site. Open the browser console: a failed component logs its name and the error, and its element carries `data-fw-component-error`. With the visitor's reduced motion setting on, a still picture or a settled scene is intended.
- Every request fails after an engine error. Restart FormWeb; the last saved state of the open site is restored. Since 0.21.0 the "protocol response mismatch" state repairs itself.

## Current boundaries

The browser application defaults to local authoring and persisted services. External adapters require server configuration and independent transport/vendor verification; a fixture response or saved binding does not prove public hosting, domain/TLS/CDN readiness or completed payment processing. Collaboration uses branches, review, roles and presence rather than simultaneous character-level co-editing. The desktop packages are built from this source by FormCompiler (the README's Download table); this repository's own checks type-check the shell and freeze the engine but do not launch a package. See the comparison in [comparisons](comparisons/) for evidence grades and every release's score and the [agent quick start](AGENT_QUICKSTART.md) for agent workflows; verification records ship in the planning sidecar.
