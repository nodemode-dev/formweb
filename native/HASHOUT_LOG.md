# Native context

## Motion, themes and the new allow-lists · v0.19.0 (2026-11-09)

The executor spec is `MOTION_SPEC.md` in the 0.19.0 planning sidecar; this entry records what the code does where it goes beyond or narrows it.

Model (`formweb-model`): `safe_style` gains 40 properties (3D transforms, clip-path, gradient masks, blend modes, individual transforms, scroll snap, container type, font variation and feature settings and the rest of the spec list); `url(` stays banned by `safe_css_value`, so masks are gradients only. Attributes autoplay, playsinline, inert, decoding, fetchpriority, srcset and sizes are allowed with value checks; `valid_srcset` runs every candidate through `safe_url` and accepts only `Nw` or `N(.N)x` descriptors. `data-fw-theme-only` must be dark or light. The design group validates `properties`, `themes` and `fonts`. `motion.rs` validates the `motion` group and owns its own number and choice helpers because `advanced::number` takes integers only; `keys`, `string`, `node` and `maps` in `advanced.rs` became `pub(crate)` instead of being copied. Scenes need `stage` and `length`, keyframes must start at 0, end at 1 and ascend strictly, and a distribute stagger must keep `(n-1)*stagger` below 1. Loop keyframes accept plain style maps or `{at, styles}` frames. Marker actions carry no trigger.

Engine (`formweb-engine`): `motion.set`, `motion.remove` and `design.set` validate right after writing, so bad input fails the command instead of the batch's final check. `prune_motion` runs in `synchronize` after `prune`: entries keyed by a removed node go, and dangling references (scene tracks, distribute parents, markers, drag flip and bounds, accordion and tab items, filter chips, action targets) are cleaned; a scene whose stage is gone or whose tracks are all gone is dropped. Emptied maps stay as `{}`; only `motion.remove` clears the group. `page.duplicate` copies the nine motion maps with the remapped ids.

Export (`formweb-export`): the head boot script sits right after `<meta charset>`, before any stylesheet; its theme part and its `fw-m`/`fw-r` part are emitted only when needed. Theme overrides are written for the non-default mode only, and only for tokens that survive route scoping; `route_styles.rs` scans the motion and themes JSON for `var(--x)` so their tokens are kept. Twin hiding falls back to the default mode through `html:not([data-theme])`. Font faces are written as `url("/api/assets/<sha>.woff2")`, the form images use; the backend's `bundle_assets` rewrites it with the right number of `../` for `assets/pages/N.css`. Reveal from-states use `:not([data-fw-in])` so the authored styles take over when `motion.js` marks an element revealed. The renderer pre-wraps split and typewriter text in `.fw-w` and `.fw-c` inline-block spans, wraps marquee children in a `.fw-track` (with `overflow:clip` on the container, or the max-content track widens the page), wraps accordion panel content in one `data-fw-inner` child (the `0fr` grid rule needs a single child), writes `data-fw-open` on the initially open panel and `hidden` on inactive tab panels, so nothing changes after first paint. `motion.js` and `interact.js` are appended to `assets/runtime.js` only when the site has a `motion` group.

Runtime (`motion.js`): the reveal reads the authored state by removing `fw-m` from `<html>`, reading computed values and restoring it in the same synchronous block with transitions off, so nothing paints in between; it commits by writing the authored values inline, setting `data-fw-in` and cancelling the animation. `once:false` snaps back to the from-state when the element leaves view. Scenes use one passive scroll listener and a frame subscription that runs only while scrolling or smoothing settles; each frame reads one rect per scene and skips scenes more than a viewport away; stage height and sticky top are cached and refreshed by a ResizeObserver. Markers fire when the smoothed progress crosses forward; a page loaded mid-scene does not fire earlier ones. The marquee shift is measured as the distance from the first child to its clone, because `-50%` drifts by half a gap. Counters detect the thousands separator from the authored text. Ghost typing uses `setTimeout` and stops while the field is focused, filled, off screen or hidden. Springs use CSS `linear()` where supported. The shared API is `globalThis.__formwebMotion`.

Runtime (`interact.js`): drag owns `translate` and `rotate`; flip and tilt own `transform`, so flip and tilt on one node would conflict. Fling rotation is the cross product of grab offset and velocity over the half-diagonal squared, capped at 720 degrees per second, and only on `axis: both`. Filter chips are single-select, and clicking the active chip returns to `all`. Accordions are multi-open unless `single: true`. Action links and buttons have their default prevented. The lightbox waits up to 1.5 s for `decode()` so its final rect is known, and assumes the thumbnail keeps the image's aspect ratio. The copy fallback appends and removes one textarea for `execCommand`.

Checked: `cargo build --release --locked -p formweb-core` and `cargo test --release --locked` (8, 20, 14, 4 and 23 tests pass, none added); throwaway pages for both runtimes in headless Chrome showed no console errors; tabs hid their panels after first paint (CLS 0.0067) until the exporter learned to write `hidden` server-side.

## Engine tests · v0.18.4 (2026-10-26)

Integration tests beside the crates, run with `cargo test --release --locked` in `native/` (the workspace excludes `formweb-render`). `formweb-model/tests/validation.rs` builds invalid trees from the starter site (missing, doubly parented and orphaned nodes, cycles, depth over 100, unsupported tags, unsafe URLs and styles, unknown breakpoints, the 8 MiB limit, CMS field types). `formweb-engine/tests/engine.rs` drives `Engine` through the command ids: undo and redo restore the exact site, a batch is one step and atomic, refused commands leave the site alone, revision conflicts, checkpoint restore in a fresh engine. `formweb-export/tests/compile.rs` compiles a three-page fixture and resolves every `href` against the exported file list, and checks the media blocks come widest to narrowest. `formweb-core/tests/protocol.rs` runs the real binary over its JSON-lines protocol. The one existing test module in `formweb-model/src/vector.rs` is unchanged.
