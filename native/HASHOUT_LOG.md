## A fragment carries its ancestor ids · v0.20.3 (2026-11-11)

`formweb-engine/src/advanced.rs`: `fragment()` adds one optional field, `ancestors`, the ids of the copied element's ancestors at the source, nearest first, ids only. `paste_fragment` adds them to the ids that can have made an ending, so a child copied out of an earlier copy and pasted into another site swaps its ending from the first paste (`label-copy-1` becomes `label-copy-N`, not `label-copy-1-copy-N`). The field is read only as an array of at most 256 strings of at most 128 bytes and is ignored otherwise; it cannot add, rename or remove nodes. A fragment without it pastes as before, a 0.20.2 engine ignores it, and the backend passes it through unchanged. Checked: `cargo test --release --locked` (69 passed); ten generations stayed at 18 to 19 characters with no duplicate ids.

## Short ids only for endings a copy made · v0.20.2 (2026-11-10)

`formweb-engine/src/advanced.rs`: a trailing `-copy-N` or `-page-N` on an HTML id (and a leading `copy-N-` on timeline and overlay ids) is swapped on copy only when `copy-N` or `page-N` is the copied element itself or one of its ancestors at the source (`node.duplicate`: in the site; `page.duplicate`: the page and its root; paste: inside the fragment). An author id such as `x-copy-5` or `step-page-2` is now appended to (`x-copy-5-copy-N`), not renumbered. This narrows the v0.20.1 rule below, which renumbered any id with such an ending.

## Copies of copies keep short ids, and copies keep their behaviors · v0.20.1 (2026-11-10)

`formweb-engine/src/advanced.rs`: a copy (paste, `node.duplicate`, `page.duplicate`) replaces an HTML id ending the engine added earlier (`-copy-N` or `-page-N`) with its own instead of appending another, when the result is free in the site; otherwise it appends as before. Author ids such as `step-copy` or `hero-2` are never shortened; an author id that itself ends in `-copy-N` or `-page-N` is renumbered like an engine one. Behavior timeline and overlay ids get the same swap on their leading `copy-N-`. Links inside the copy (label `for`, `aria-labelledby`, `href="#id"`, node interactions and behavior actions with a `#id` url) follow to the copy's own ids. Also fixed: copying a node used to drop its `behaviors.nodes` entry (its button actions); copies now keep it, pointed at the copy.

## Variables, scripts, search, page components and code sections · v0.19.1 (2026-11-10)

The executor spec is `TURN_B_SPEC.md` in the 0.19.1 planning sidecar; this entry records what the code does where it goes beyond or narrows it.

Model (`formweb-model`): `formula.rs` holds the one formula language for both sides. Text converts to a number only when it is an optional `-`, digits, an optional `.digits` and an optional exponent after trimming (no `+`, no `.5`, no `5.`); `variables.js` uses the same rule. Comparison is textual only when both sides are text, in UTF-16 code-unit order, as JavaScript's `<` does. `&&`, `||` and comparisons give booleans; `lookup` turns a number key into text through `number_text`; `sum` adds only the numeric entries of a table; division or remainder by zero and any non-finite result give 0; `round(x, d)` clamps `d` to 0 to 10. `number_text` prints integers in full digits (so 1e21 and up never use an exponent) and other numbers with up to 10 decimals, trailing zeros dropped, never `-0`. Output formatting rounds half away from zero, puts the minus sign after the prefix (`$-5`), and prints booleans as `true` or `false`. `evaluate` resolves formulas depth first; a cycle reads as 0, though validation refuses cycles. `hidden` joined the attribute allow-list (empty or `true`), because script and search templates must carry it. Script steps: `stream` and `type` require `text`; `append.text` may be empty; `play` is refused inside a script's `action` step to rule out recursion; a `submit` script needs a `form` node; `loop` only with load or view triggers. Code: `poster` takes image extensions only; `asset` props also take mp4, webm and woff2; a section host must have no children and `sections` needs `allowSections: true`.

Engine (`formweb-engine`): `motion.track` revalidates the whole `motion` group, so an empty `tracks` list is refused. `variables.*` and `code.*` commands run the full `validate_extensions` (there is no per-group entry point). Pruning on node removal drops a whole script when any step names the node (targets, templates, `into`, `from`, pointer and scroll `to`, `{input:node}` tokens, nested actions), and drops search actions naming it; `set-variable` is untouched. `page.duplicate` does not copy variables bindings, scripts or code sections.

Export (`formweb-export`): outputs are written with their formatted initial text and route CSS reserving `min-width` in `ch` (plus `inline-block` for inline tags), so first paint shows the final numbers; on narrow screens a non-wrapping row of reserved outputs can overflow, which is the author's layout to wrap. `boot_script` also emits for `--fw-v-*` values alone. Page-mode hosts get `data-fw-component` and a poster `img`; `:where([data-fw-component]){position:relative}` and the poster rule are written only on pages that have a page-mode host, and `components.page` is added to the config only when non-empty, so sites without these features export byte for byte as before. Section CSS is appended in node-id order. `asset-access.json` gains the component and section script files. A form that is the trigger of a `submit` script and has no `forms` entry is written without `action`, `method`, `data-fw-form` and the status line (`advanced::script_form`), so the forms runtime does not post it to `/api/forms`. The search index skips nodes carrying `hidden`, so templates stay out of it.

Runtime: every runtime file ends with `})();` and a newline, since `motion_runtime` concatenates them without separators. `variables.js` queues re-entrant `set` calls from subscribers and flushes up to 100 turns. `interact.js` gained a `default` branch that calls `globalThis.__formwebActions[name]`, exposes `globalThis.__formwebRun`, and fires the `input` trigger. `play.js` ignores triggers during a run unless `restart`, bumping a run id so stale steps exit; results are marked `data-fw-result` so authored siblings in the results container survive; clones keep `data-fw-node` so authored styles apply, and node lookups skip clones. `components.js` imports each component once per id, resolves the module URL against `document.baseURI`, keeps the poster's box (`visibility:hidden` after `ready()`), restores the poster and removes the layer on any failure, swallows callback errors into `data-fw-error`, and reads assets already rewritten by the backend's `bundle_assets`. `motion.js` notifies `onProgress` subscribers from inside the scene frame loop, so no second animation frame loop stays alive while the page is idle.

Checked: `cargo build --release --locked` with no warnings and `cargo test --release --locked` (69 tests pass, none added). 46 formulas evaluated by `formula.rs` and by `variables.js` gave identical values and identical formatted text. A site built through the API (calculator with three bound inputs, three outputs and a `set-variable` button, a chat script on a form, a looping demo script with a fake pointer, site search over two pages, a page component inside a scene, a code section) exported and passed the webspun `shoot.py` bar in four runs (dark and light at 1440, dark at 390, dark at 1440 with 4x CPU and a slow network): 0 console errors, 0 page errors, 0 foreign requests, no overflow, CLS 0. Driving it: the outputs read `$348/mo` and `$4,176/yr` at first paint and `$1,475/mo` and `$14,160/yr` after input; the chat appended and streamed; `?from=/about/pricing-plans` filled the search and listed the About page; the component drew, hid its poster after `ready()`, and the section script ran. The only layout shift during interaction came from the search's empty message appearing, and it carries `hadRecentInput` when typed from the keyboard.

## Motion, themes and the new allow-lists · v0.19.0 (2026-11-09)

The executor spec is `MOTION_SPEC.md` in the 0.19.0 planning sidecar; this entry records what the code does where it goes beyond or narrows it.

Model (`formweb-model`): `safe_style` gains 40 properties (3D transforms, clip-path, gradient masks, blend modes, individual transforms, scroll snap, container type, font variation and feature settings and the rest of the spec list); `url(` stays banned by `safe_css_value`, so masks are gradients only. Attributes autoplay, playsinline, inert, decoding, fetchpriority, srcset and sizes are allowed with value checks; `valid_srcset` runs every candidate through `safe_url` and accepts only `Nw` or `N(.N)x` descriptors. `data-fw-theme-only` must be dark or light. The design group validates `properties`, `themes` and `fonts`. `motion.rs` validates the `motion` group and owns its own number and choice helpers because `advanced::number` takes integers only; `keys`, `string`, `node` and `maps` in `advanced.rs` became `pub(crate)` instead of being copied. Scenes need `stage` and `length`, keyframes must start at 0, end at 1 and ascend strictly, and a distribute stagger must keep `(n-1)*stagger` below 1. Loop keyframes accept plain style maps or `{at, styles}` frames. Marker actions carry no trigger.

Engine (`formweb-engine`): `motion.set`, `motion.remove` and `design.set` validate right after writing, so bad input fails the command instead of the batch's final check. `prune_motion` runs in `synchronize` after `prune`: entries keyed by a removed node go, and dangling references (scene tracks, distribute parents, markers, drag flip and bounds, accordion and tab items, filter chips, action targets) are cleaned; a scene whose stage is gone or whose tracks are all gone is dropped. Emptied maps stay as `{}`; only `motion.remove` clears the group. `page.duplicate` copies the nine motion maps with the remapped ids.

Export (`formweb-export`): the head boot script sits right after `<meta charset>`, before any stylesheet; its theme part and its `fw-m`/`fw-r` part are emitted only when needed. Theme overrides are written for the non-default mode only, and only for tokens that survive route scoping; `route_styles.rs` scans the motion and themes JSON for `var(--x)` so their tokens are kept. Twin hiding falls back to the default mode through `html:not([data-theme])`. Font faces are written as `url("/api/assets/<sha>.woff2")`, the form images use; the backend's `bundle_assets` rewrites it with the right number of `../` for `assets/pages/N.css`. Reveal from-states use `:not([data-fw-in])` so the authored styles take over when `motion.js` marks an element revealed. The renderer pre-wraps split and typewriter text in `.fw-w` and `.fw-c` inline-block spans, wraps marquee children in a `.fw-track` (with `overflow:clip` on the container, or the max-content track widens the page), wraps accordion panel content in one `data-fw-inner` child (the `0fr` grid rule needs a single child), writes `data-fw-open` on the initially open panel and `hidden` on inactive tab panels, so nothing changes after first paint. `motion.js` and `interact.js` are appended to `assets/runtime.js` only when the site has a `motion` group.

Runtime (`motion.js`): the reveal reads the authored state by removing `fw-m` from `<html>`, reading computed values and restoring it in the same synchronous block with transitions off, so nothing paints in between; it commits by writing the authored values inline, setting `data-fw-in` and cancelling the animation. `once:false` snaps back to the from-state when the element leaves view. Scenes use one passive scroll listener and a frame subscription that runs only while scrolling or smoothing settles; each frame reads one rect per scene and skips scenes more than a viewport away; stage height and sticky top are cached and refreshed by a ResizeObserver. Markers fire when the smoothed progress crosses forward; a page loaded mid-scene does not fire earlier ones. The marquee shift is measured as the distance from the first child to its clone, because `-50%` drifts by half a gap. Counters detect the thousands separator from the authored text. Ghost typing uses `setTimeout` and stops while the field is focused, filled, off screen or hidden. Springs use CSS `linear()` where supported. The shared API is `globalThis.__formwebMotion`.

Runtime (`interact.js`): drag owns `translate` and `rotate`; flip and tilt own `transform`, so flip and tilt on one node would conflict. Fling rotation is the cross product of grab offset and velocity over the half-diagonal squared, capped at 720 degrees per second, and only on `axis: both`. Filter chips are single-select, and clicking the active chip returns to `all`. Accordions are multi-open unless `single: true`. Action links and buttons have their default prevented. The lightbox waits up to 1.5 s for `decode()` so its final rect is known, and assumes the thumbnail keeps the image's aspect ratio. The copy fallback appends and removes one textarea for `execCommand`.

Checked: `cargo build --release --locked -p formweb-core` and `cargo test --release --locked` (8, 20, 14, 4 and 23 tests pass, none added); throwaway pages for both runtimes in headless Chrome showed no console errors; tabs hid their panels after first paint (CLS 0.0067) until the exporter learned to write `hidden` server-side.

Three more shifts surfaced on a 134-node site built through the API (a capture-wall scene, reveals, marquees, counters, accordion, tabs, filter, drag, typewriter, ghost input and video) and are fixed: the web font swapped in after first paint (0.0013 at 1440, text sources), so `boot_script` now also writes `<link rel="preload" as="font" crossorigin>` for every woff2 face, and `font-display` defaults to `optional` (the formai.studio kit's own choice), because on a slow network even a preloaded face can arrive after the block period and `swap` would then reflow every line; counters wrote "0" into a grid column sized by "76" (0.0012 at 390 px), so `motion.js` pins the counter's `min-width` to the authored text's width before the first write. After the fixes the webspun `shoot.py` runs (dark and light at 1440, dark at 390, dark at 1440 with 4x CPU and a 150 ms, 200 KB/s network) all report zero console errors, zero page errors, no foreign requests, no overflow and CLS 0.

## Engine tests · v0.18.4 (2026-10-26)

Integration tests beside the crates, run with `cargo test --release --locked` in `native/` (the workspace excludes `formweb-render`). `formweb-model/tests/validation.rs` builds invalid trees from the starter site (missing, doubly parented and orphaned nodes, cycles, depth over 100, unsupported tags, unsafe URLs and styles, unknown breakpoints, the 8 MiB limit, CMS field types). `formweb-engine/tests/engine.rs` drives `Engine` through the command ids: undo and redo restore the exact site, a batch is one step and atomic, refused commands leave the site alone, revision conflicts, checkpoint restore in a fresh engine. `formweb-export/tests/compile.rs` compiles a three-page fixture and resolves every `href` against the exported file list, and checks the media blocks come widest to narrowest. `formweb-core/tests/protocol.rs` runs the real binary over its JSON-lines protocol. The one existing test module in `formweb-model/src/vector.rs` is unchanged.
